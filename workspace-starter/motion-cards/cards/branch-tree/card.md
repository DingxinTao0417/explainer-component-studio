## 命门

1. **枝线画到底，选项才存在。** 每条枝线在 cue 之前 0.45 秒从问题下方出发，cue 那一帧到达，选项这时才弹出来。选项先摆好再补线，读成“给三个框连上线”，不是“从问题里分出来的路”。
2. **列举和选择是两个阶段，亮法不一样。** 列举时：当前选项白字加强调色描边，讲过的变灰。选择时：被选中的整块填成强调色、放大到 1.1 倍、它的枝线加粗到 16px 回到全亮；其余选项是灰字，枝线降到 30%。列举时就把某一个填亮，等于提前剧透；选择时只是描个边，分量不够。
3. **问题节点始终是白的、不动的。** 它是所有枝线的起点，观众要靠它记住“我们在回答什么”。问题在选项出来后变暗或缩小，树就没有根了。

## 参数手感

| 参数（脚本顶部 CFG） | 默认 | 调大 | 调小 |
| --- | --- | --- | --- |
| draw 枝线绘制时长 | 0.45s | 过 0.7 线比旁白慢 | 低于 0.2 线是闪出来的 |
| optIn 选项落位时长 | 0.32s | 过 0.5 发软 | 低于 0.18 没有“长出来”的感觉 |
| win 选中后的倍数 | 1.1 | 过 1.2 五个选项时会碰到邻居 | 1.0 时只靠填色，可以但弱 |
| lose 落选枝线的亮度 | 0.3 | 过 0.6 和选中的分不开 | 0 时树只剩一根线，看不出是选出来的 |
| fill 选中填色时长 | 0.12s | 过 0.25 选中发软 | 0 是硬切 |
| fonts 各条数的字号 | 104 / 96 / 80 / 64px（2 / 3 / 4 / 5 个），问题 104px | 三个四字选项在 96px 时放大后已经占满 600px 的列 | 低于 56px 选项读不清 |

## 已知坑

- 枝线用 `pathLength="1"` 归一后画，不用量曲线长度；线帽用平头，圆头在还没开始画时会在起点露一个点。
- 选中时字色要换两次：先在 hit 那一帧切回白色（它可能已经是灰的），填色淡到一半再切成深色。直接从灰切到深色，中间有几帧是灰字压半透明的黄，读不出来。
- 选项的宽度跟着字数走，但字号按“列宽 ÷（字数 + 1）÷ 1.16”封顶，保证放大后不碰邻居。整排宽 1800px，问题和选项的框都高 200px。五个选项时每列 360px，三个字是 64px，四个字就掉到 56px。
- `pick` 填 0 表示不选：这时最后一个选项会一直保持白字描边，没有收尾。这种用法只适合“先列出来，下一镜再选”。
- 选项只排一行。超过五个或者有第二层分叉，这张卡做不了，拆成两镜：先分大类，再在选中的那一类下面分一次。

## 动效与皮的边界

属于这张卡的：枝线从同一个根出发、线先到选项后出、列举时逐个点亮并退灰、最后一次性地选中一个并压暗其余。

只是皮：枝线是曲线还是折线、节点的形状、选中用填色还是打勾、根在上面还是在左边（横着分叉也成立）、强调色。

## 接进片子

- `question`：顶上的问题。`items`：选项，`|` 分隔，2–5 个。`pick`：选中第几个（从 1 数），0 表示不选。
- `cues`：前几个数是每个选项出现的秒数，对齐旁白说出这个选项的词；最后多写的一个数是“选中”的时间，对齐旁白说“我们选……”“更好的是……”的那个词。第一个不早于 0.7 秒。
- `backdrop`：`off` 时透明，问题和选项都自带底板，枝线是细线，底下画面太花时先压暗。
- 音效：每条枝线出发时一个轻的 draw，选项落位时一个 pop，选中那一帧一个 chime。
- 接法：选中以后，下一镜直接展开被选中的那一项（录屏或 `flow-nodes`）；想在选中时把其余部分压得更暗，叠一层 `spotlight-dim`。
