## 命门

1. **一次只有一步在跑。** 下一步的圆弧要等上一步打完勾 0.37 秒（详情停 0.25 秒、淡出 0.12 秒）才转起来，蓝色底带也跟着挪下去。几步的圆弧一起转，读成“并行下载”，不是“代理按顺序干活”。
2. **调用是敲出来的，结果是整行冒出来的。** 第一行（调用，如“读取 src/login.tsx”）每秒至少 45 个字符逐字出现，后面跟一个方块光标；第二行（结果）在第一行敲完 0.1 秒后整行出现。两行都逐字敲，结果行要晚 0.3 秒以上才出完，打勾前根本读不到；两行同时冒出来，又没有“代理在调用工具”的感觉。
3. **打勾那一下所有东西同时变。** 圆弧在 0.18 秒内收没、勾从 0.06 秒起一笔画出、图标鼓到 1.18 倍、字从灰变深、进度条前进一格、计数加一（0.08 秒后弹到 1.25 倍）。这些分开发生，观众会以为是几件事；只换图标不变字色，远看分不出哪几步做完了。

## 动作拆解

默认 4 步、`cues` 留空时，四步在 1.8 / 3.1 / 4.4 / 5.7 秒完成（第一步 1.8 秒，之后每 1.3 秒一步）。下表 S 是某一步开始转的时刻，C 是它完成的时刻。

| 时间 | 谁 | 做什么 | 缓动 |
| --- | --- | --- | --- |
| 0.05 → 0.5s | 面板 | 从下方 30px（竖屏 26px）升上来，同时淡入 | power3.out |
| 0.2s 起，每行晚 0.05s，各 0.3s | 步骤行 | 从左边 28px（竖屏 24px）滑进，全是灰字、空心圆 | power3.out |
| S → +0.22s | 这一步的圆弧 | 从 0 长到圆周的 28%，淡入 | power2.out |
| S → C+0.2s | 圆弧 | 每秒 1.4 圈匀速绕圈（转的是描边的虚线偏移，不是旋转元素） | none |
| S → +0.3s | 详情块、蓝色底带 | 详情块撑开，下面的行往下让；底带挪到这一步：下沿 0.15 秒就盖住新的一行，上沿跟着上一块收起用 0.3 秒挪下来（第一步时底带 0.25 秒淡入） | 下沿 power3.out，上沿和详情块 power2.inOut |
| S+0.2s 起 | 详情第一行 | 等宽字逐字敲出，≥45 字符/秒，方块光标跟着 | 逐字 |
| 第一行敲完 +0.1s，最晚 C−0.3s | 详情第二行 | 整行出现 | 瞬间 |
| C → +0.18s | 圆弧 | 收短到 0，C+0.16s 起 0.04 秒淡没 | power2.in |
| C+0.06 → +0.26s | 勾 | 沿手画的笔画描出 | power2.out |
| C → +0.1s → +0.28s | 图标 | 1 → 1.18 → 1 倍 | power2.out，back.out(3) |
| C → +0.2s / +0.4s | 步骤文字 / 进度条 | 灰 → 正文色；进度条前进 1/n | power2.out / power3.out |
| C+0.08s | 计数 | 加一，1 → 1.25 → 1 倍 | power2.out，back.out(3) |
| C+0.25 → +0.12s | 详情块 | 淡出 | none |
| C+0.37 → +0.3s | 详情块 / 下一步 | 收起，同时下一步的块撑开（两者相加总高不变） | power2.inOut |
| 最后一个 C+0.37s | 底带 / 小结的位置 | 底带 0.25 秒淡出；面板底部让出小结那一行 | power2.out / power2.inOut |
| 最后一个 C+0.59 → +0.4s | 小结标签 | 从左端放大 0 → 1（不透明，不淡入） | back.out(1.7) |

默认在 6.29 秒弹出小结，6.69 秒全部落定，之后静止到 7 秒。

失败（`fail` = 第几步）时，那一步的 C 换成：圆弧照样收没，叉分两笔画出（C+0.06s、C+0.2s 各 0.16 秒）；图标先向右跳 9px 再衰减晃回原位（0.32 秒）；步骤文字和详情的结果行变强调色，进度条和底带一起变强调色；详情不收起，后面的步骤一直是灰的、不开始；C+0.52s 弹出小结，C+0.92s 落定。

## 参数手感

| 参数（脚本顶部） | 默认 | 调大 | 调小 |
| --- | --- | --- | --- |
| CFG.first / CFG.gap 默认完成时刻 | 1.8s / 每步 1.3s | 2s 时结果行能完整停 1.2–1.3 秒，旁白可以念出细节；再大圆弧空转太久 | 低于 1.3s 第一行要提速敲（1.2s 时 16 个字符要每秒 70 个），结果行停的时间也到底了：约 0.55 秒（`read` 0.3 秒加 `keep` 0.25 秒），最短的 0.9 秒一步只剩 0.43 秒 |
| CFG.minGap 最短一步 | 0.9s | — | 再小下一步的块还没撑开就打勾了 |
| CFG.cps 最慢打字速度 | 45 字符/秒 | 过 70 看不出逐字 | 低于 30 一行 16 个字符要半秒多，挤掉结果行的阅读时间 |
| CFG.read 结果行最晚提前量 | 0.3s | 过 0.6s 第一行被迫打得很快 | 0 时结果行刚出来就打勾，读不到 |
| CFG.bandIn 底带下沿到位 | 0.15s | 和 `open`（0.3s）一样长时，底带中途半盖着新的一行，像慢了半拍 | 低于 0.08s 下沿是跳过去的 |
| CFG.keep 打勾后详情停留 | 0.25s | 每加 0.1 秒，结果行多停 0.1 秒，但下一步晚 0.1 秒开始、第一行敲得更急：默认 1.3 秒一步时改成 0.45，第二步 17 个字符要在 0.13 秒里敲完（每秒约 130 个），看不出逐字 | 0 时勾还没画完详情就没了 |
| CFG.spin 转速 | 1.4 圈/秒 | 过 2.5 像在报错狂转 | 低于 0.8 一步只转小半圈，看着像卡住 |
| CFG.arc 圆弧长度 | 圆周的 28% | 过 50% 像一个缺口的圆，看不出在转 | 低于 15% 只剩一个点 |
| CFG.mark 勾的描画时长 | 0.26s | 过 0.45 像慢动作 | 低于 0.15 看不出笔顺 |
| LAND / PORT 字号 | 标题 56 / 56px，步骤 50 / 46px，详情 40 / 34px | 步骤 6 条时横屏已占到 1040px 高（见已知坑） | 详情竖屏低于 32px 手机上读不清 |

## 已知坑

- **竖屏的等宽小字。** 详情竖屏是 34px（横屏 40px），这是底线：再小手机上读不清。次要色 #6b7280 压在 #f4f5f7 的面板上对比度约 4.4:1，压在蓝色底带上约 4.1:1，别再调浅字色或加深底带。失败那一步的强调色字压在橙色底带上只有约 3.1:1，靠的是 40px 以上的大字；底带不透明度第一版是 8%，算下来只剩 3.0:1，现在是 6%。Consolas 没有中文，中文退回雅黑、一个字 1em 宽，西文 0.55em；脚本按这个估宽，超出就截断加“…”：横屏一行约 27 个汉字或 50 个西文字符，竖屏约 19 个汉字或 35 个西文字符。路径、命令写短一点，别指望它换行。
- **转圈不用旋转。** 第一版转的是包着圆弧的 `<span>`（`rotation` 补间），`verify` 报 `rotation_pivot_drift`：上一步收起时这一行往上移一个详情块的高度（两行时横屏 120px、竖屏 112px），检查把“边转边移”当成转轴错了。现在圆弧是一个带 `pathLength="1"` 的圆，转圈靠 `strokeDashoffset` 从 0.25 往下减（每秒 1.4），没有变换，行怎么移都不报。别改回旋转。
- **失败时的抖动只能从一边起跳。** 想写“从 0 出发、晃几下回到 0”的单段补间，得用末端不等于 1 的缓动（如 `sin(3πp)·(1−p)`）；MT 1.2.0 在补间结束后直接显示终点值，不按缓动在 1 处的值算，图标会停在 −9px（GSAP 停在 0）。现在写成从 +9px 起、缓动末端等于 1 的衰减余弦，并加 `immediateRender: false`，免得失败前图标就偏 9px。
- **结果行停得短。** 默认节奏（每步 1.3 秒）下，结果行（如“12 个测试全部通过”）只完整停 0.55–0.64 秒（再淡出 0.12 秒），第一行停 0.65–0.74 秒：观众能扫到“有调用、有结果”，读不完 9 个字以上的结果。这是有意的，默认是“代理在飞快干活”的质感。旁白要念出细节时，相邻 cue 隔 2 秒，第一个 cue 不早于 2.5 秒，结果行能停 1.2–1.3 秒。不要靠加大 `keep` 解决（见参数手感）。
- **面板高度会变。** 详情块撑开、收起、小结让位都会改面板高度，面板的顶边按“最高的那一刻”（一块详情开着；失败时是详情加小结）定好不动，所以开头和结尾面板下沿会比中途高一点。最满的情况（6 步、两行详情、失败加小结）横屏面板从 y≈40 到 1040，竖屏标题两行时从 245 到 1295（68% 线是 1306），已经顶满，别再加字号或行高。
- **标题和步骤太长。** 标题横屏一行，先从 56px 缩到最小 40px，再截断加“…”；竖屏最多两行。步骤横屏 50px 约 22 个汉字、竖屏 46px 约 14 个汉字开始缩，缩到 40px 还放不下就截断。步骤字号不超过标题：标题缩到 44px，步骤也最大 44px，免得表头比行还小。第一版按“汉字 1em、西文 0.55em”估宽，全大写或 W、M 多的英文比估算宽：竖屏一条 `WWW MMM …` 的步骤伸出画面 44px，大写标题折成三行而面板按两行排（6 步时下沿会超过 68% 线）。现在先估，再把字放进去量实际宽高（`scrollWidth`、`offsetWidth`、`offsetHeight`），超了每次缩 2px，到 40px 再逐字截断；小结标签同样按实测截断。详情是等宽字，0.55em 本来就准，仍按估算截断。
- **竖屏标题只有 56px。** SPEC 五-4 要求竖屏标题 72–120px，这张卡的标题是面板的抬头（界面元素），按界面比例比步骤大一级就够；改成 72px，两行标题多占 42px，最满的情况面板下沿会超过 68% 线。data-table 最挤的竖屏也是把标题压到 56px。

## 动效与皮的边界

属于这张卡的：一次只跑一步；圆弧匀速转、完成时收成手画的勾；调用逐字敲、结果整行出；打勾时字色、进度条、计数一起变；失败时画叉、变强调色、后面的步骤不再开始；全部完成才弹小结。

只是皮：面板圆角和阴影、底带的颜色和左边那条竖线、圆弧和勾的粗细、勾的笔形、计数写成“2/4”还是“2 of 4”、小结标签的样式、标题冒号前灰色小标签的有无。换成深色皮（`--mc-*`）照样成立，进度色用 `--k-accent-2`，失败色用 `--k-accent`。

## 接进片子

- 变量：`task` 任务标题（第一个冒号前、5 个字以内的部分显示成灰色，如“任务：”“目标：”）；`steps` 步骤，`|` 分隔，2–6 步，每步 4–14 个字最好；`details` 每步的调用细节，`|` 和步骤一一对应，步内用 `;`（或全角 `；`）分两行（第一行写调用、第二行写结果），某一步不要就留空（`a;b||c`），整张不要详情就写空字符串（或 `|`）。**改了 `steps` 一定要同时写 `details`**：只改步骤、`details` 还是默认的登录页细节时，脚本当作没有详情（不然登录页的细节会挂到新步骤下面）；`cues` 每步完成的秒数，逗号分隔，留空按 1.8 秒起每 1.3 秒一步，只写前几个时按已给出的 cue 的平均间隔往后排（只给一个时每步 1.3 秒，如 `2,2.5,5` 四步时第四步在 6.5 秒），第一个不早于 1.65 秒，相邻至少 0.9 秒（有两行详情的步至少 1.3 秒，否则第一行敲得太快）；`fail` 第几步失败，0 是全部成功；`summary` 小结文字，`fail` 不为 0 且没改过默认值时自动写成“第 N 步失败 · 已停下”；`backdrop` 填 `off` 只留面板，压在录屏上用。
- 起始时间：让每一步的 cue 对上旁白念完这一步的那个词（“读完了”“改好了”）；第一步 0.75 秒开始转，所以旁白说第一步之前留出 0.75 秒。旁白要念出详情里的结果（“12 个测试全部通过”）时，相邻 cue 至少隔 2 秒，否则结果行只停 0.6 秒左右（见已知坑）。片段时长至少写到最后一个 cue 后 1.3 秒（失败时失败那一步后 1.2 秒），默认 4 步是 7 秒、6 步约 9.6 秒。
- 音效：每个 cue 后 0.06 秒（起笔）一个轻 tick；小结弹出（最后一个 cue 后 0.59 秒）一个 chime；失败那一步的 cue 用 impact，不放 chime。逐字敲的地方可以垫很轻的 type，不垫也行。
- 横竖两用：片段写 `data-width="1920" data-height="1080"` 是横版，写 `1080` × `1920` 是竖版，变量和节奏不变；竖屏面板宽 80%，排在 12%–68% 的主体区里，锚线在 40%。
- 常和这些卡连用：前面用 `code-walk` 讲要改的代码，这张卡演代理怎么做；某一步要细看命令输出时接 `terminal-log`；做完回顾成果用 `checklist-tick`。
