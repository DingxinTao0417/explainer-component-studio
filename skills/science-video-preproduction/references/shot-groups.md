# 镜头组：从观看顺序到组件选择

设计多镜头讲解、重排段落或修复“看着完整却没看懂”时使用。镜头组是一段连续的理解过程，可由一个持续变化的镜头或多个镜头完成；不规定组数、镜头数或统一秒数。只改字号、颜色等局部样式时不重做全片设计。

## 先决定观众怎样理解

在选组件前，为每组写出：

- **任务**：观众进入时知道什么、还不明白什么；看完能判断或做什么。
- **观看顺序**：先识别对象，再看关键变化，最后看到结果或引向下一问题。顺序可随内容调整，但不能省掉结论依赖的证据。
- **景别分工**：全貌交代对象与位置，局部展示关键条件或操作，回到全貌验证变化。不机械轮换远中近；局部放大后保留对象身份、位置或返回线索。
- **动作链**：初态、触发条件、关键变化、终态及阅读停留。结果依赖前一步时，前一步完成后再呈现结果；彼此独立的信息可并行展开。
- **声画分工**：画面提供可见证据，旁白解释关系、原因与边界；强调文字只提重点。逐字字幕可重复声音用于辅助阅读，不因此删掉必要字幕。

再选择能实现上述任务的组件、实录或素材。检查组件的内容容量、内部可变状态与衔接能力；组件不适合时换布局或补实现，不让组件默认演示决定本期叙事。B-roll 要交代情境、对象或变化，不能只因一段声音长就填无关素材。

## 相邻镜头怎样连接

对实际相邻镜头写清“连接依据 + 切法 + 可观察切点”，可选信息/因果、动作、空间、视觉、声音或情绪连接。例如：

- 信息连接：条件高亮并停留后，硬切到按同条件筛出的明细。
- 空间连接：从表格全貌推近状态列，保留行号与选中行，核对后回全表。
- 视觉连接：上一镜条件卡缩到固定位置，下一镜沿用同一张卡继续展示结果。
- 声音连接：旁白跨镜延续同一个问题，下一镜在提及对象时出现；不为了声桥重排未经授权的配音。

只有对象形状、方向或遮挡真实对应，才使用匹配转场；遮挡类转场须覆盖完整成片画布。普通硬切也可以是正确选择，说明它交接哪条信息即可。只写“平滑转场”“高级感”或方法编号，不能指导制作。

## 保存到现有计划

整期制作在 `planning/DIRECTING.md` 按组记录：`组 ID｜镜头 ID｜理解任务｜观看顺序｜景别与动作链｜声画任务｜结果/出口`；只引用 `EDIT.json` 的镜头 ID，不另外维护时间区间。

实际实现细节放在 `EDIT.json.scenes[]` 的可选字段：`group_id`、`viewer_delta`（本镜增加的理解）、`transition_to_next`（`basis, cut, trigger`）、`sound_role`、`method_ids`。沿用已有动作与验收字段，避免重复描述。只写稿或前期包时写入现有分镜即可，不建立整期 JSON 台账。

制作前检查：每镜是否有新信息、动作变化或必要的阅读停留；移除这一镜会失去什么；关键证据是否出现且读得完；结果是否有可见来由；下一镜是否让观众重新辨认全部对象。重复画面若用于对照、记忆回收或阅读，可保留并写清职责。
