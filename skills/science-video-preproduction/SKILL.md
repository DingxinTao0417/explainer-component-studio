# 科普视频编导与制作

让用户只提供“想讲什么”，就得到能拍、能录、能找素材、能剪辑的完整编导包。先设计观众看到什么与为什么继续看，再选择画面来源。制作或更新 skill 本身不触发示例素材搜索、制图、配音或视频生成。

要求按期建立独立项目、结合稿件和配音用 HyperFrames 制作完整视频/字幕/配乐时，由 [science-video-director](../science-video-director/SKILL.md) 负责全流程。本技能被它调用时仅提供所需的编导方法，不再次路由、不重复建立旧版制作包；使用主流程的项目契约。

整期制作由主编导接收 SRT、对应音频、design.md；纯前期策划仍可从主题开始，不因此强索三项。主编导采用 `user_handoff` 时，按 [用户生成视频素材交接](../science-video-director/references/user-video-handoff.md) 完成编导、参考图流程、逐镜视频提示词和回传清单，交付后等待用户生成视频；不能按下文的 H3 默认继续提交。没有生图能力时先交详细生图提示词并等待实际图片，不能宣称参考图齐备。主流程使用 EDIT/ASSETS，目标平台未定可先交通用动作草稿，模型专属参数留待适配；不运行旧版 PRODUCTION 包的 H3 专用严格校验来替代该交接检查。

## 从最少输入开始

- 先读取用户的原话、已有稿件和本项目材料。保留核心观点与语气；用户给定原稿时区分“整理润色”和“改写扩展”，不悄悄替换论点。
- 当前个人工作环境和偏好见 [references/project-defaults.md](references/project-defaults.md)。只沿用适用的选择；用户本次要求优先。
- 主题已明确即可工作。受众、时长未说明时，依据材料采用普通成年人受众、约 3 分钟横屏讲解作为可调整初稿，并在简报写明；不让用户先填长表。不为了凑时长编造内容。只有主题含义或用户立场的歧义会改变结论时，才简短询问，同时继续独立准备。
- 按请求范围交付：只要稿就写稿；要制作包就完成其中已授权的制图、素材检索与录屏策划。要“找素材”就给查证过的候选来源，不能只给搜索关键词；要实际参考图且工具可用时完成制图，能力缺失则按下文交付详细提示词并说明图片待生成。用户只让创建本 skill、没给主题时，完成 skill 并提供调用方法即可。

## 编导：开头、正文、结尾

写稿前读取 [references/directing.md](references/directing.md)。先明确观众的问题、核心结论、开头承诺及正文如何兑现。开头同时设计口播与第一幅画面，通常给 2–3 个简短钩子候选，推荐一个并用于完整初稿；正文用演示、证据、例子或推理推进；结尾回扣开头，提炼能带走的方法或一个可执行动作。不编造对比结果、用户收益或第一人称经历来增强钩子。

在分镜中记录各段职责（hook / body / ending）、画面证据、悬念何时回答、需要用户拍摄或录屏的部分。正文的每段要带来新信息，不用重复吊胃口替代解释；不预设机械的切镜频率。

## 内容与逐字稿

1. 写出一句观众看完应理解或能做到的事。建立因果链或解释顺序，每段都承担明确作用；按题材选择问题、例子、对比、原理或应用，不强行套统一爆款结构。
2. 对外部事实、专业机制、数字与时效性结论核对一手来源，记录支持什么、适用条件和不确定性。把用户观点、事实和视觉类比分开。缺乏依据时收窄或删除断言，不把用户想法包装成研究结论；不虚构第一人称经历。
3. 输出一份完整、可直接朗读的简体中文逐字稿：短句、口语、具体例子，解释术语。逐字稿纯文本不混进镜头编号、配音指令、来源脚注。辅助说明写在分镜或事实核对文件。
4. 分镜中的旁白必须完整覆盖最终逐字稿，保持顺序，不漏句、不无意重复；任何改稿同时更新对应分镜。没有新配音时，时长和节奏都明确为估算，不伪造精确 SRT。

## 先选画面来源，再拆镜

为主编导制作配套视频时，按 [组件库生产协议](../science-video-director/references/component-library-integration.md) 先用库的 director-index 按理解任务检索，查看实际内容、动作节点与预览。分镜具体绑定候选组件、外观和需要填入的内容，或说明选择其他来源的理由。已实现能力与本期新方案分开；不凭记忆写 ID，不用统一 8 秒节奏代替音频规划。生图提示词同时注明将素材装入哪个组件或画面层。

设计多镜头讲解时，先按 [镜头组设计](references/shot-groups.md) 确定理解任务、观看顺序、景别与动作链、声画分工，再选画面来源和组件。每个相邻镜头写明连接依据、实际切法与可观察切点。出现开头空泛、过程跳步、信息重复等具体难点时，按症状读取 [讲解方法卡](references/explainer-methods.md)；只选适用方法，编号不能代替制作说明。

每个镜头指定主要来源：`ai_animation`、`ai_image`、`external_video`、`external_image`、`screen_record`、`graphic` 或 `user_media`，写明选它的理由。软件按钮、输入和实际效果优先真实录屏；真实事件/案例查找可核对的素材；抽象机制与难拍过程适合动画；精确数据、流程和关键文字适合可控图解。按讲解需要混用，不设任意比例。

外部素材和录屏都读取 [references/assets-and-recording.md](references/assets-and-recording.md)：

- **外部素材**：通用实拍照片或视频优先通过 Pexels API 获取，按 [Pexels 与 image2 素材](../science-video-director/references/pexels-image2-assets.md) 实际搜索、查看并下载采用项；事实证据仍找官方/原始资料或实录。交付具体页面、作者/机构、对应镜头、拟用片段、画面作用和使用条件。没查看的视频不能编造精确时间码。找到来源、可用、已下载是不同状态。
- **本人录屏**：交付准备条件、起始页面、准确的操作步骤、可复制输入内容、预期可见结果、对应旁白、停顿/强调/剪辑点及失败替代方案。实际核对当前 UI 或官方说明；不确定的按钮和步骤标为待核实，不伪装成已演练。用户负责录制时交付逐步清单；录屏策划不自动执行演示中的外部操作。

相邻镜头统一旁白、关键文字样式、画幅和视觉重点。真实证据、真实录屏和示意动画的身份要清楚；不能让生成画面冒充软件真实效果。一个复杂合成镜头可以拆为连续子镜头，用编号关联插图或补充素材，避免全部塞进 H3。

## AI 镜头的画面设计

每镜一个理解目标，优先一个连续动作，必要时安排两三个依次发生的局部动作。AI 动画按自然语义拆镜，通常约 5–10 秒；较长句子先拆分。真实操作录屏的原始 take 可以更长，区分实际操作耗时、原始录制时长和最终剪辑时长，不套 H3 帧网格。

每镜至少确定：对应旁白、讲解目标、事实或类比性质、构图、主体数量、初态、动作、终态、固定不变的对象、字幕留白与转场衔接。数字、符号方向、步骤顺序、完成/未完成的差异必须与讲稿相符。

先区分参考图职责：主体/画风参考、构图目标、真实首帧或目标终态。**一张全要素终态图不等于可强制执行的首帧或末帧约束。** 如果关键知识依赖精确初态、数量或不变区域，优先生成符合初态的图；目标终态另做校验图，仅在当前工作流支持时接入对应约束。不要用互相冲突的文字弥补错误的参考图。

## 实际生成 AI 参考图

- 先执行 [风格参考与生成能力分支](../science-video-director/references/design-and-generation.md)：向用户索取生图风格参考，已明确指定的直接复用；剧情板用途不清时先确认。检查当前 Agent 实际可调用的生图工具，有能力就完成已授权制图，没有则交详细生图提示词、参考绑定和返回规格，等图片回传后再审查。视频继续由用户生成并回传，不因具备视频工具而自动提交。
- 制图前读取 [references/visual-and-motion.md](references/visual-and-motion.md)。确定画风、线条、材质、色彩语义、主体比例、镜头尺度和重复对象的统一规格。
- 有已选定的画风时实际查看其参考图，写清“只借画风”与“复用主体”的区别。新主题不要沿用旧视频的文件夹、山水海报、文字或论点。
- 定制前景元素和特殊背景按用户选定的 image2 生图路线，读取当前 `imagegen` skill，并按可用内置 `image_gen` 的实际 schema 调用；具体模型标识按实际信息记录。透明前景、背景和精确文字分层，生成后核对真实 alpha 与实际合成效果，详见 [分层素材规则](../science-video-director/references/pexels-image2-assets.md)。局部修改也用图像编辑工具；不以简单占位图冒充已生成素材。精确图表和现有 Logo 继续使用可控图形与图标库。
- 先做一幅代表性参考图并检查风格与动画可行性。现有画风已明确且用户已要求整套时，检查合格即可在授权范围内继续其余图；用户要求先确认风格时等该确认，不逐张索取重复许可。
- 图生视频参考图按每镜准备独立完整画面，不把分镜拼贴、文字说明页或接触表直接当首帧输入。用于 HyperFrames 合成的透明元素则按独立对象输出，背景另做，不受“一镜一张整图”限制。检查并记录实际尺寸；按本期画幅预留必要安全区，不能仅修改文件名就宣称分辨率达标。
- 多镜共用环境时先单独准备 ENV 环境图，固定布局、视角关系、材质与光源，动态对象另做。无生图能力则给独立环境图提示词；只有单首帧输入的平台使用环境与主体合成后的完整首帧，不能拿分镜拼图代替。
- 工具返回后查看真实图片，检查主体、数量、状态、中文、形状和误导性视觉。只做必要的定向修正，避免无限追求美术变体。保留候选，项目采用图复制到项目目录，记录实际路径和 SHA-256。

## 图像提示词与视频提示词分开

图像提示词描述一个静止时刻和画面职责；视频提示词描述随时间发生的变化。先写制图提示词，再看生成的实际图，最后修正视频提示词，不把未实现的细节写成已存在。

只有 `ai_animation` 镜头需要视频提示词；静态 AI 图不强制转视频，外部素材、图解和录屏不需要伪造制图/视频提示词来满足格式。目标为 H3 时依照可用的 `h3-science-video` 技能及其 `references/prompt-and-quality.md` 六字段规范：英文镜头描述，已有中文原样保留；素材编号按计划输入顺序，提交前再按实际节点绑定核实。主编导人工交接使用其他平台时按其实际能力适配，不强行套 H3 字段。素材没生成时可以交草稿，标为 draft，不能宣称可直接提交。

逐镜按 [详细视频提示词字段](../science-video-director/references/design-and-generation.md#视频提示词必须逐层逐对象逐时段) 写初态、各主要对象动作或静止状态、路径/接触/遮挡、相对时间、运镜、环境与光影变化、终态和衔接，并交可复制完整提示词；复杂镜头另附动作表。动作与实际参考图一致，图片未回传则标待参考图核对。默认画面阶段不生成旁白或配乐，新配音由最终合成输入负责；精确字幕、公式和关键标签单独排版。

## 配音与 H3 衔接

- 保留用户声音偏好。已有对应新稿配音时使用原速音频；只有旧稿配音或旧音色素材时，不能当作新稿配音，也不能声称已具备可调用的声音模型。
- 只有文字时先完成逐字稿、分镜、参考图与提示词。新配音若缺少可用工具或授权，就明确标记待配音；已授权且接口可用时按实际配音工具执行，不凭空创造节点、模型或服务能力。
- 收到新音频后重新测时、校对文本对应关系，生成真实时间轴和 SRT；目标为 H3 的 AI 动画按当前 H3 帧网格调整镜头，其他平台核对其实际时长限制，已有素材按剪辑时间轴安排。先录演示后配音、或按已有旁白补录都可，按用户工作习惯选择。长操作可以剪掉等待或明确加速；不截断必要步骤，也不把剪辑后的速度当作软件实测速度。
- 制作包准备不等于授权所有镜头付费生成。用户要求生成哪一段或哪一批，就按现有授权调用 `h3-science-video`；已有授权不重复问，不自动付费重试。默认交接当前 Budget 配置，运行时核实实际可用节点。

## 文件与交付检查

按 [references/package-contract.md](references/package-contract.md) 落盘。使用一个项目目录和稳定镜头编号，版本更新保留旧候选；只为实际交付创建文件。

运行 `python -X utf8 scripts/check_package.py <项目目录>` 检查逐字稿覆盖和各类素材映射。加 `--for-video` 检查各镜进入生成/剪辑前的静态条件：AI 动画核对 H3 输入，录屏核对计划与实际录制文件，外部素材核对具体来源及采用文件。它不替代事实审查、ComfyUI 节点绑定、录屏演练或媒体审片。

最后交付钩子/正文/结尾方案、完整逐字稿、带画面来源的分镜、实际素材检索结果、本人录屏清单、所需 AI 图与提示词和制作清单。说明哪些已准备、哪些需要用户录制、哪些素材待获取以及配音状态；只展示真实产物。不要把脚本通过、单帧检查或工具成功当作科学正确、运动稳定或声音试听已验收。
