# 视频编导与制作

仓库发行版使用配套组件库；初次在新机器调用先读 [安装与路径](references/installation.md)。运行时使用显式 `--library`、`EXPLAINER_COMPONENT_LIBRARY` 或安装记录定位库，仓库内直接调用则自动识别当前仓库。文档中 `skills/...` 命令以仓库根目录为工作目录；已安装技能按实际技能目录展开。项目与媒体由调用者提供，历史参考、音色和凭据不随技能分发。

把用户的稿件、配音和资料组织成能看懂、能验证、能继续编辑的完整视频。每期一个独立项目；内容决定画面，配音决定时间轴。只要求创建或修改本 skill 时不启动整期视频制作；适配用户指定的本地模型时可用隔离短样验证，不扩大到整片重做或未授权云端生成。

## 可恢复状态与确认闸门

新项目和接续项目都先读 [可恢复状态与流程留痕](references/workflow-state.md)。`PROJECT.json` 是状态唯一真源，`episode.py status` 用于跨会话恢复，`qa/workflow-events.jsonl` 只做追加式追溯。用户确认后的策划内容有指纹；方案被直接改动时必须重新确认，不能沿用旧确认。状态报告、事件记录和结构检查都不能替代真实听看、独立审片或用户导出决定。

## 总编导、制作与独立审片

整期制作采用三角色协作，先读 [分工与交接](references/team-workflow.md)。当前主助手担任总编导，持有用户决定、内容主线、风格和唯一时间轴；制作 Agent 按有限任务包制作；独立审片 Agent 读取原始要求、参考和实际产物后给出缺陷与验收结论。角色是运行时分工，专业 skill 是共用方法；`agents/openai.yaml` 只是入口信息。

- 默认安排一位制作 Agent 和一位独立审片 Agent，按依赖顺序启用，无需同时占满并发。小范围修改可由总编导直接制作，再交独立审片；仅讨论、写稿或改 skill 不启动视频制作团队。
- 使用当前可用的子代理工具派工，不创建用户侧的新任务。只有镜头足够独立且并行有收益时才拆出更多制作任务；共享规范不变、写入范围不重叠，禁止递归扩张团队。
- 审片者不能是该版的总编导或制作者；制作自检不能替代独立审片。审查绑定工程指纹与镜头覆盖记录；修改画面、声音、字幕或素材后重验受影响部分及相邻转场，不能继承旧版通过结论。
- 不支持委派或用户明确要求单 Agent 时按 [降级方式](references/team-workflow.md#无法独立委派时) 执行，真实标明自审与未覆盖项，不虚构独立审片。

## 开始与接续

整期制作先按 [输入与生成规则](references/design-and-generation.md) 收齐 **SRT、对应音频文件、design.md**，已有文件直接读取，只请用户补缺失项。用户让助手代写 design 时先完成；三项不齐可继续理解与策划，不能声称整片素材已就绪。只写稿、更新 skill 或生成 design 不要求先提供完整三项。实际音频决定时间，design 决定本期视觉与叙事约束，EDIT 仍是唯一正式时间轴。

1. 先读本期材料与已有项目记录；接续旧项目先运行 `episode.py status`，确认用户要策划、预览还是成片。收到“用稿件和配音制作视频”即推进可播放工程与视觉审查，不只交计划；新项目仍先按第 3 步取得开场确认。有待用户生成的 AI 视频时，先完成下述交接包并停在待回传，素材回来后再接续。默认按“视觉审查 → 预览选择 → 导出确认”流程交付，不把一般制作请求视为自动导出授权。用户明确要求直接导出或本次已有仍有效的明确导出决定时，审查通过后执行，不重复询问；明确只预览则不导出。导出授权本身不改变 AI 视频由谁生成。
2. 新一期读 [本机预设与复用方式](references/local-pipeline.md)，使用 `scripts/episode.py init` 建立 `./projects/<日期>_<主题>/`，复制本期输入并登记哈希。接续时读取 `PROJECT.json`，不要重新初始化或混入其他期的稿件、配音。媒体采用项目内相对路径。
3. 新项目先做 [开场策划与用户确认](references/opening-plan.md)：默认用当前可用的原生选项问答工具，让用户点击选择尚未确定的整体风格、背景、边框与声音偏好；已有明确选择不重复问。按讲解目的检索组件库，展示实际截图、试听文件和画廊链接后再让用户选具体候选。把选择写成 `planning/PROPOSAL.json` 并渲染 `planning/PLAN.md`，展示完整方案后询问是否“确认方案，开始编导和制作”，**停在这里等确认**。选偏好不等于同意制作；未确认前不写编导稿、分镜稿，不建镜头，不启动 HyperFrames 制作。用户改选后更新提案再确认。普通模式有问答工具时直接使用，不要求先切 `/plan`；工具选择、等待与降级规则见上述参考。
4. 确认之后才展开 `DIRECTING.md` 与分镜/时间轴，并进入下述制作。已有本期配音为主时间依据；缺配音时先按三项输入清单请用户提供，用户明确要求助手生成才按 [本地 Qwen 配音](references/local-qwen-tts.md) 使用已选本地 Qwen3-TTS 和音色。缺 SRT 时同样先请用户补齐，已授权转写/对齐才执行。生成前可做策划并标估算时间，生成后按实测声音更新；不能用旧期声音、静音或估算字幕冒充本期完成。

## 编导先于套模板

- 需要多款方向箭头或文字框、同语义等级整片统一时，读 [方向箭头与语义标注](references/semantic-annotations.md)：先按语义角色冻结文字框，再按方向与路径筛选箭头并用确定性 seed 选择。关联大括号不能替代有头部的指向箭头。

- 本用户要求**尽可能混剪**，作为默认编导策略。每个旁白段落先设计有内容作用的素材组接：Pexels 等有来源的实拍图片/视频、用户录屏、用户提供或按交接要求制作并回传的视频承担主体画面，组件按需承担图解、对比、标注、标题与衔接。优先安排真实操作、相关实拍、细节、结果及必要图解之间的接力，再选择组件；能直接用素材表达时直接用，组件也可叠加在素材上，不默认把整段装进一个完整模板。
- 混剪看素材之间如何补充信息、承接动作和引导注意力；只给同一张图换动效、换边框或在组件之间轮播，不算落实该策略。完整图解用于确需解释的关系与过程，保留充分阅读和操作时间。每段写清素材顺序、各自职责、连接理由及缺口；连续纯组件段落说明内容依据。主动检索缺少的合适素材，必要时给出具体补录/生成交接任务，不因素材未齐就默默退回整段组件动画。不设机械比例、固定切镜间隔或来源数量，不为混剪插入无关画面；本期用户要求优先。
- 开场先盘点已有素材与缺口，再依次确认整体风格、背景、装饰边框、素材组接与辅助组件、动画转场、音乐音效及完整方案；这些选择服务于分段混剪方案，详细顺序见 [开场策划](references/opening-plan.md)。
- 本 Skill 与用户组件库配套，先读 [组件库生产协议](references/component-library-integration.md)。组件调用必须走“讲稿意图 → 少量候选 → 实际 props/effect 兼容性 → 配置校验 → 用户确认 → 导出并接入”的链路：用 `scripts/library_prepare.py prepare` 调库内 `component-intents.mjs` 找候选和理由，用 `director.mjs inspect` 与返回的嵌套 `propsSchema` 精查（`example`/`props` 仅是演示配置），用 `compatibleEffects` 筛动作，再用 `scripts/library_prepare.py validate` 给出具体字段错误；需要生成配置时用原生 `director.mjs compose`，需要在已筛候选中做确定性变化时用 `library_prepare.py vary`。校验失败不能静默截断、换成演示默认值或继续写 EDIT。本期 design 与已确认的开场策划案锁定系列与外观，EDIT 记录具体绑定或其他来源的理由。确认前不导出 v5、不写入 EDIT；确认后 `component_library.py bind` 会再次校验并检查确认指纹，再实际接入工程，通过绑定检查；不以“建议复用”、仅换背景或导出但未接入作为已使用组件。
- 确定各类镜头样式、落实用户参考或修正构图时，读 [镜头分层与动态复查](references/scene-composition.md)。背景、装饰外框、内容窗口、字幕与转场分别选择；本用户默认软件演示去外框仍保留滚动背景，主题卡精简不等于关闭字幕。把本期例外写进 design，不能将“全加边框”等早期决定覆盖用户后续修正。
- 用户提供参考片、指出风格差距，或希望对标某种视频效果时，先读 [参考片对标与样片验收](references/reference-benchmark.md)。实际查看参考与当前版本，写出有时间点依据的差距及本期修正；不能只继承配色就宣称对标完成。
- 调用 [science-video-preproduction](../science-video-preproduction/SKILL.md) 的编导方法，并按需读取其中 directing、assets-and-recording、visual-and-motion 参考；本项目采用下述单一数据契约，不再复制一套旧版制作包账本。
- 多镜头编排先按 [镜头组设计](../science-video-preproduction/references/shot-groups.md) 明确观看顺序与声画任务，再选组件与逐镜实现。具体难点按 [讲解方法卡](../science-video-preproduction/references/explainer-methods.md) 查找；组计划引用 EDIT 镜头 ID，切点与实现沿用唯一时间轴。
- 明确观众的问题、开头承诺、正文如何兑现、结尾带走什么。需要钩子且已有配音时，用结果画面、问题字幕、对比和节奏设计，不擅自添加用户没说过的话；用户选择直接进入正文时沿用该决定。需要改口播则写补录建议及对应句子；用户接受改稿或重排声音后才同步更改配音剪辑计划和字幕。
- 逐段选择最能解释内容的画面：需要证明真实软件能力或本次实际结果时用实录；软件案例讲解可按用户选择采用观察后的可编辑界面复刻；真实事件或实例用有来源的资料；精确数据/流程用可控图解；抽象过程用动画。不要把全部旁白重复贴成 PPT，也不按固定秒数机械切镜。
- 分镜写清讲解目标、对应声音时间段、画面初态/动作/终态、来源、必要文字、运动、转场、声音及验收点。核实事实和软件能力；生成的 UI、画面和结果不能冒充实际操作证据。
- 编排动画、动效、转场和音效时，按 [整片动态多样性](references/motion-variety.md) 使用有约束的随机：先筛合适候选，再避开同类组件与相邻镜头的重复家族，保留直接切镜、静止和安静。策划时固定 seed 与候选范围，制作时冻结实际配置；播放器不随机抽选，用户已指定的处理不被覆盖。
- 分镜同时标明每段采用的用户材料、库组件、实录或外部素材，以及未就绪的具体缺口。纯图解是内容判断，不是省略素材与录屏流程的默认选项；假设案例可用标明示意的动画，真实输入、操作和核对步骤仍可安排录屏。

## 按顺序落实素材

B-roll 模板只提供布局与动效框架，示例图片/视频不构成本期素材选择。按每期内容主动检索并填入 Pexels、已核实的网络素材或用户素材，逐槽替换主/辅助画面；开场方案同时展示框架和实际素材，缺口标待补。具体槽位和换图规则见 [组件库接入](references/component-library-integration.md)。

需要额外图片或视频时，读 [素材检索与 H3 制作](references/assets-and-h3.md)：先检查用户材料和可复用资产，再按用途选择路线。通用实拍照片或视频优先通过 Pexels API 搜索、查看并下载；定制透明前景元素或特殊背景使用用户指定的 image2 生图路线，不必先等待图库检索失败。具体获取、透明通道和合成要求见 [Pexels 与 image2 素材](references/pexels-image2-assets.md)。真实事件或软件能力的证据仍使用可核对来源或实录。

外部候选必须记录具体素材页、作者、许可依据和采用理由；未下载、未看过、许可未核实分别留状态。复用本地素材时也保留来源。image2 生图与编辑按当前 `imagegen` 技能和真实工具能力执行；生成的主体、背景与可编辑文字分层，在 HyperFrames 中做位移、遮罩、景深和焦点交接，实际检查风格与 alpha 边缘。静态素材配合可控动画足以表达时直接合成；需要主体形变或连续物理动作时，按下面的用户交接模式准备生成镜头。仅在用户明确选择由 Agent 调用视频模型时走自动生成路线；目标为 H3 才调用 [h3-science-video](../h3-science-video/SKILL.md)，核实当前节点。本流程生成视频默认只取画面，配音、字幕、BGM 与动效声由 HyperFrames 独立处理。

素材选择和首次生成属于用户所请求的制作流程；是否能提交付费调用依据本次已有的服务、范围、次数/预算授权。若缺口会产生未授权费用，先完成可检查的镜头、提示词和工作流，再就缺口一次询问；不重复索取已有许可。每次提交保存任务 ID 与状态，结果不确定时先查询，不重复扣费重提。

## AI 视频：交参考图与提示词，等待用户回传

生图先按 [输入与生成规则](references/design-and-generation.md) 请用户给生图风格参考图；已经明确提供的直接复用，用途不明的剧情板先确认是否也作画风依据。随后检查当前 Agent 实际可调用的生图/参考编辑能力：有能力就在已有授权内直接生成并查看；没有能力则交详细生图提示词、参考绑定及回传规格，标“待用户生图”。同一环境的多个生成镜头，先准备独立环境参考图或环境生图任务，固定布局、光源和材质供各镜引用。

本用户已确认视频仍由本人生成并回传，默认 `settings.ai_video_mode: user_handoff`。按 [用户生成视频素材交接](references/user-video-handoff.md)，先走上述生图流程，再写逐对象、逐时段的视频提示词，覆盖每个主要对象的动作/静止、运镜、环境变化、终态和衔接。有图后核对实际内容才能标“可用于图生视频”；无生图能力时可同时交视频提示词草稿，但停在“待参考图回传”，不能假称图片已齐。参考图和视频提示词齐备后停在“待用户生成视频并回传”；不代为提交视频模型，不用静态推近冒充缺失镜头，也不提前交整片。此偏好不强制每期加入 AI 视频。

已收到全部所需视频时直接检查并接续，不重复要求生成；没有新 AI 视频缺口时不设这道等待。用户明确让 Agent 生成时记录为 `agent_generate` 并沿用已有调用授权，不重复确认；单说“继续”不改变交接方式。回传后按同一镜头 ID 核对实际视频、可用区间、首尾衔接和声音，合格后插入原时间轴，再完成全片独立审查、预览选择与导出。缺片或需要补生成时只交代剩余项，保留已合格素材。

## 软件画面：实录或组件复刻

用户明确选择“先通过电脑操控观察应用，再复刻组件模拟工作”时，读 [观察与界面复刻](references/ui-reconstruction.md)，采用这条路线并更新本期计划；该选择覆盖默认由用户录屏，不再把用户交录屏作为这些镜头的前提。只有需要证明真实能力、实际结果或仍有独立实录需求的镜头才保留录屏任务。复刻只承诺已经观察、制作并验证的范围，不将本次选择扩大为每期强制 1:1 复刻。

需要实录时读 [录屏操作脚本](references/recording.md)。按镜头交付起始页面、准备文件、逐步操作、可复制输入、预期可见结果、画面停留、对应旁白及补录办法。先查实际 UI 或当前官方文档，标明“已演练 / 文档核对 / 待核实”。未另作选择时默认用户录制，写计划不等于执行软件中的外部操作。

每项有效实录需求给文件名与放置位置。缺少所需录屏时用显式占位做草稿，列出待录清单；继续制作其他镜头。收到录屏后核对内容、清晰度、采用区间和讲解对应关系，再替换占位并重新检查。占位不能进入最终交付；已选择并完成的界面复刻不是待补录屏的占位。

## 声音、字幕与 HyperFrames 合成

执行制作前读取当前 `hyperframes` 入口并遵循其路由；多场景、混合录屏的自定义讲解通常使用 `general-video`。本 skill 负责整期内容编排，不替代 HyperFrames 的媒体时序和渲染规范。

扩展已有组件库（包括 B-roll）时，先读该库的 `CONTRACT` 与设计规范，沿用颜色、字体、圆角、阴影和动效语气；不因内容类型变化自行更换视觉风格，用户明确要求改风格时除外。真实素材保留原色，字幕与必要标注沿用本期样式；是否加装饰外框按镜头类型及本期要求决定。先完成一个代表性金样，与原库同屏对照核对风格后，再批量展开。

组件默认是起点。需要适配镜头或改善观感时，按 [组件调参与视觉微调](references/component-tuning.md) 主动 inspect → tune → 预览比较 → 迭代；根据实际 propsSchema 修改本期实例的布局、字号、样式与动作。按对象身份决定颗粒度，例如车及投影整体调用，卸货才拆货物；不把可实现的内部零件一律当作独立调用单位。

复用或维护组件时读 [组件模板与本期内容分离](references/component-templates.md)。共享组件默认使用通用占位内容，适用于所有类别，不限动画风；本期文案、消息、代码与数据通过本期配置传入，不回写为库默认值。用户要求全库模板化时，覆盖默认配置、源码中的固定内容、动画示例、组合示例、预览和缩略图；普通视频制作只处理本期采用的组件，不自动启动全库改造。

按 [音画制作与验收](references/postproduction.md) 完成：

1. 探测真实媒体参数，转写并用稿件校对声音，保留原速、原声及完整语义，建立旁白剪辑映射。
2. 从实际声音对齐字幕，检查术语、数字、断句、首尾和连续长段同步；输出 UTF-8 SRT、VTT 及画面内字幕。稿件与声音不一致时记录差异，不把未说内容塞入字幕。
3. 在本期 HyperFrames 工程复用当前组件库和已修正的透视背景，按信息需要安排真实素材、图形、圈注和转场。按本机复用说明逐镜记录实际组件、改动与路径；只借配色或网格不算采用了其他组件。默认保持白底、Codex 蓝、薄荷绿；用户明确的新风格优先，参考片的色彩与可迁移的镜头方法分别判断。真实软件 UI 等比显示。
4. 按已确认策划案的音乐方向，检索并取得使用条件适用的纯音乐 BGM，按段落配曲；改换已确认曲目要有用户后续决定。音乐在人声下自动压低，首尾淡入淡出，动作音只在明确落点出现。旁白、BGM、SFX 分轨，AI 视频默认静音。不得漏放用户配音。
5. 制作方完成工程与音画自检，总编导整合后交独立审片；完成当前版本的审查与返修复查后，再让用户选择预览，随后确认是否导出。导出决定明确后才渲染整片，再检查实际导出的音视频，不把浏览器预览通过当成导出验收。

## 视觉审查 → 预览选择 → 导出确认

整期审片同时读取 [叙事与理解审查](references/narrative-review.md)，检查观众是否能跟上证据、变化和结论，而不只检查画面有没有技术错误。先保留成立的处理，再将主要根因转成具体返修；摘要聚焦重点，完整缺陷仍进入现有 findings。局部修正按影响范围复查，不重做无关策划。

全片工程做好后，制作方先自检，总编导冻结待审版本，独立审片 Agent 实际查看各镜头的代表画面、关键转场动态与音画对应关系，按 [音画制作与验收](references/postproduction.md) 记录问题、返修并复查。代码检查、截图成功、旧版或组件库的 QA 都不能代替本期审片；审查未通过时继续修正，不把问题留给用户验收。版本与审查记录格式见 [独立审片角色](references/roles/reviewer.md)。

通过后简述审查结果，先让用户选择是否在内置浏览器预览；选择预览就打开审查通过的同一版本，再根据反馈修改、复查，之后询问是否导出。选择跳过预览也仍需明确导出决定；“看一下”“可以预览”不等于同意导出，未回复不等于选择。已有明确导出决定不重复索取，用户最新指令优先。内部审查可使用预览、截图或必要的小段测试，不能先导出完整交付视频再补问用户。

用户已经明确选择预览方式时，审查通过后直接按选择执行；已说“暂不导出”时保持该决定，不重复索取同一选择。

## 项目记录与交付

数据结构、目录和助手命令见 [项目契约](references/project-contract.md)。`PROJECT.json` 管输入与设置，`PROPOSAL.json` 与 `PLAN.md` 管开场策划与用户确认，`EDIT.json` 管实际时间轴，`ASSETS.json` 管素材及许可，`RECORDINGS.json` 管待录与实录，`CAPTIONS.json` 管已对齐字幕。人类可读的编排和录屏说明从这些记录派生；避免两份时间轴互相冲突。

用 `scripts/episode.py check <项目目录> --phase plan|ready|review|delivery` 检查对应阶段；它只核对文件、时序、台账与审查记录约束，不能证明画面/声音质量或许可判断。`ready` 是制作结构检查，`review` 再核对独立性、当前版本和覆盖证据；新协作项目的 `delivery` 还要求有效审查。阶段检查发现缺失时保留可用成果，明确哪些待补，不降格宣称成片完成。

最终提供项目位置、可播放预览或成片、SRT/VTT、录屏清单、素材来源/署名、未完成项和下一步。成片交付保留可编辑工程和原始素材；本地制作不自动包含公开发布。
