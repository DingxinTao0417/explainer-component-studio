# 科普视频编导与制作

目标是做出让人愿意看完、看得懂、看着有质感的讲解视频，并且一期比一期好。

衡量标准是用户喜欢的三条抖音 AI 教程，拆解见 `guide/visual-grammar.md` 和手法库。它们都是：开头先亮结果，画面里有人，录屏、大字卡和比喻画面轮流出现，字大，节奏快，主色鲜明。它们还有一个共同点：不是“这个题目最常见的那种视频”。所以每期都要先发散、再收敛。

流程和记录都为这个目标服务。该问用户的事一次问清楚，其余由你判断并推进。

## 一、七条标准

设计时照着做，自查时逐条核对。数字是 1920×1080 下的起点，可以按题材调整，但偏离要说得出理由。

1. **前 8 秒给看点。** 第一个画面就放本期的结果、反差或问题，比如做出来的东西、一个惊人的数字、一个人卡住的瞬间，并配大字标题。8 秒内至少换 3 次画面。观众在前几秒决定划不划走，标题卡和空镜留不住人。
2. **画面里有“人”。** 按本期决定用真人口播、固定插画角色、头像角标或故事主角。至少出现在开头、每次换章和结尾，情绪转折处也可以出现。人能带来信任和情绪，纯图解再清楚也显得冷。
3. **四类画面轮流出现。** 四类是：主持人（带情绪）、证据（录屏、真实结果、原始资料）、结构（章节卡、关键词卡、大数字）、比喻 / 情境（插画、示意动画、组件、Pexels 情境实拍）。
   - 讲解段每 2–5 秒要有一次看得见的变化：换画面、换景别，或明显的状态变化。
   - 同类画面连续不超过约 20 秒。同一素材或同一个比喻，全片出现 3–4 次以内。
   - 旁白每出现一个新名词、数字、对比或步骤，画面上都要有对应的变化，而且卡在这个词被说出的那一刻（用 `align.py find` 查时间）。变化不等于加东西：新元素只在一个意思单位的开头进场，说完就让位，同屏最多 3 组。
   - 类型换了，版式也要换：同一种构图不连用 3 镜。
4. **字要大。** 章节卡标题 120px 以上，关键词卡 90px 以上，画面里的标签至少 40px，字幕约 56–64px、加粗、带描边。主体宽度至少占画面 60%，默认不套装饰外框。简单检验：接触表（每格 480 宽）里看不清的字，手机上也看不清。
5. **录屏铺满，并告诉观众看哪里。** 录屏和真实界面铺满画面，操作区推近到字看得清。用主色框圈出重点，框外压暗。结果出现后至少停 1 秒。网页和长文档用滚动、停靠、放大“拍”出来，不贴一张静止截图；框和下划线的位置读实测坐标，不目测。
6. **一个主色，高对比。** 每期按调性配方定底色和一个主色，全片统一。质感来自强对比、光影和大块深色或留白，不是多种浅色叠在一起。
7. **进度看得见。** 用“01 / 第一步”这样的章节卡，让观众知道讲到哪、还剩多少。

还有两条底线：
- 生成或复刻的画面不能冒充真实操作结果：编出来的对话、数字、运行结果在画面内容里写“示例数据”，不把复刻的回复包装成真实结果。
- 用户的口播原话不擅自改。

角标（“情境示意”“界面示意”“实拍 Pexels”）默认不加，用户要求时才用 scenario-tag（2026-09-28 起，用户两期都去掉了角标）。

## 三、流程

### 1. 开工：收材料，问三个决定

- **接续旧项目**：先运行 `episode.py status <项目>`，读 `planning/NOTES.md`。旧项目里的 PROPOSAL、handoffs、审片 JSON 这类记录只当历史参考，不再是继续制作的前提。
- **重做已交付的一期**（用户说“这期重做”“按新标准再做一版”）：运行 `episode.py stage <项目> brief --note "重做：<用户原话>"` 回到构思阶段，按新一期走构思和样片。旧成片当作要超越的对象，用户夸过的部分保留。
- **新一期**：
  - 运行 `episode.py init --slug <简称> --title <标题> --srt … --voice … --design …`。
  - `<工作区>/频道复盘.md` 里有数据行时，读最近三行，以及上一期 `planning/RETRO.md` 里的“下一期试什么”。
- **准备输入**：通常用户会给 SRT、配音和 design.md。
  - 只有稿子：用本地 Qwen 配音，见 `guide/voice.md`。
  - 只有主题：先用 science-video-preproduction 写稿。
  - 已有的材料直接读。缺什么，一次说清楚。
- **问三个决定**：先把两张调性静帧做好，再用选项框一次问完。design.md 或用户原话里已经写明的，直接沿用，不再问。
  - **主持人**：真人口播（你写台词和拍摄要求）/ 固定插画角色 / 头像角标 / 用故事主角代替。固定插画角色第一次用时，按 `brand-kit/assets/host/HOST_PROMPTS.md` 先出设定图，和这三个决定一起给用户确认。表情组在写 BRIEF 时做，不用再单独确认。以后各期直接复用。
  - **调性**：从 `guide/visual-grammar.md` 第 6 节挑两个适合题材的配方，运行 `node <工作区>/brand-kit/tools/tone-stills.mjs --out <项目>/qa/tones --tones A,B --line1 … --line2 … --highlight … [--bg <本期素材截图>]`，约半分钟得到两张带本期钩子文字的静帧和一张对比图，让用户对比着选。已有用户素材的，用 `--bg` 放进去。
  - **素材路线**：本期有哪些录屏、真实结果、Pexels 实拍、用户视频、AI 视频可用，哪些要用户去录或生成。
- **优先级**：本期三个决定和用户这次说的话，优先于 design.md 里的旧设定。旧设定指结构和样式方面的要求，比如白底虚线外框、配色、片头长度。冲突时更新项目里的 design.md 工作版，并在 NOTES.md 记一句。design.md 里关于内容含义的约束（哪些词不能混、哪些结论不能下）照旧遵守。
- **记录决定**：运行 `episode.py stage <项目> brief --host … --tone … --materials …`。

### 2. 构思，写导演阐述

按 `guide/ideation.md` 做，再按 `templates/brief-template.md` 写 `planning/BRIEF.md`（一到两页）：

- **三处发散**：核心洞察、视觉母题、钩子，每处写 5 个候选。5 个候选里至少 2 个是“普通模型不太会想到”的尾部方案（估计概率低于 0.10），再做剪影检查，然后挑一个。取舍写进 BRIEF 的“备选与取舍”。定稿已经定了的部分，只发散画面，不改稿。
- **手法卡**：查手法库 `INDEX.md`，点名 2–3 张作为本期的招牌手法。
- **惊喜时刻**：每期至少一个观众猜不到的时刻，放在全片 35–70% 的位置。
- **BRIEF 的其余内容**：观众和一句话结论，前 8 秒逐秒怎么抓人，分几章（每章让观众明白什么、用哪几类画面、素材从哪来），调性、主持人出场点、声音，样片选哪一段、做几版，缺口和分工。

这一步不列组件目录、候选清单或逐镜分镜，那些是制作阶段的事。

### 3. 做动态样片，给用户看

- **选段**：选最能代表全片、也最没把握的一段，15–20 秒。通常是开头 8 秒加一段正文，正文里要有证据画面和结构卡。
- **做几版**：满足 ideation.md 第 4 节的条件时，做两版探索样片：A 是推荐方案，B 是最强的尾部方案。有子代理时，按 `templates/explore-agent.md` 派两个子代理并行做。其余情况做一版。
- **用真东西做**：
  - 用真实配音、brand-kit 组件、真实字幕样式和真实素材。缺的素材用明确标注的占位代替。
  - 关键词出现的时间用 `align.py find` 卡准。
  - 渲染出 `exports/sample_v1.mp4`（两版就是 `exports/explore/A|B/sample.mp4`），低清即可。
- **先自查**：用 `frames.py` 看一遍，两版时加 `--compare` 并排看，把明显的问题先修掉。
- **交给用户**：把 BRIEF 和样片一起给用户，只问一个问题：“按这个方向做全片吗？哪里要调？”两版时问：“选 A、选 B，还是混着用？”然后运行 `episode.py stage <项目> sample`。
- **收到回复**：
  - 用户认可：运行 `episode.py stage <项目> production --note "<用户原话>"`。
  - 用户有意见：改样片，再给他看。

这是全片开工前唯一的确认点。用户能判断的是动起来的样子，文字策划和组件截图判断不了。改 20 秒的样片很便宜，整片做完再改很贵。

### 4. 全片制作

- **分镜**：写进 `planning/EDIT.json`，这是唯一的时间轴。
  - 每个镜头写明 `type`（host / evidence / structure / metaphor）、画面、素材、画面文字、动作、音效。用到品牌组件的写 `component`，用到手法卡的写 `technique`，要卡在词上的写 `cue_words`，版式写 `layout`，借了动效卡的写 `motion`。
  - 每一镜先定 type，再运行 `shot_semantics.py suggest --edit planning/EDIT.json --scene <镜号> --captions subtitles/CAPTIONS.json --transcript subtitles/transcript.json`：它给出意图、候选或“不用组件”、按旁白填好的槽位草稿和卡词时间。章节起点加 `--chapter-start`。候选写进镜头的 `intent` / `component` / `slots`，超字数按它的 strategy 缩写或拆屏，不缩字号。
  - 先排版式节奏：把全片每一镜的 `layout`（人在哪 / 素材装在哪）填一遍，摊开看有没有连着几镜一个样，再写逐镜细节。
  - 先按旁白节拍排，再对照第 3 条标准查节奏。`episode.py check` 会统计四类画面的占比、同类画面连续了多久、同一版式或组件有没有连用 3 镜，并核对每个卡词在旁白里的时间。规划阶段它报“素材未登记”是正常的，素材到位后用 `episode.py add` 登记输入、在 ASSETS.json 登记素材即可。
- **声音和字幕**：
  - `align.py run` 生成逐字时间和字幕；
  - 对白段用 `voices.py speak`；
  - BGM 闪避用 `audio.py envelope`；
  - 音效按 `sfx-map.json` 放。
  
  细节见 `guide/production.md` 和 `brand-kit/SOUND.md`。
- **素材**：按 `guide/assets.md` 准备：录屏任务卡、真人口播任务卡、Pexels、网页证据（`pageshot.mjs`）、image2 透明元素、AI 视频交接（由用户自己生成）。需要用户动手的，一次写进 `planning/TASKS.md` 交出去，然后继续做不依赖它的部分。
- **合成**：
  - 按 `guide/production.md` 搭 HyperFrames 工程。先运行 `brand-kit/build.mjs --project <项目>/hyperframes` 装品牌包。
  - suggest 给 `custom` 时现场做一镜：先用 `vocab.py find` 查有没有现成的动法，再用 `shot_semantics.py scaffold` 起品牌风骨架，照着卡的动法、用品牌包的皮画这一镜（见 `guide/components.md`“现场做一镜”和 `guide/motion-vocabulary.md`）。
  - 章节卡、字幕、录屏聚焦、取景框、主持人头像都用品牌组件，全片复用。界面复刻、图解这类画面，用组件库（场景配置 `appearance` 写本期 `tone` 和 `mode: "video"`）或定制镜头，见 `guide/components.md`。
  - 组件的默认样式只是起点，放大、改色、去外框都是正常操作。
- **边做边看**：每做完一章就抽几帧看看，不要等全片做完才发现方向偏了。能用静帧回答的问题（位置、遮挡、文案、层级）不渲视频。

### 5. 自查 → 用户预览 → 导出

1. **自查**：
   - 渲染全片低清预览，运行 `frames.py <预览.mp4> --cues planning/EDIT.json`。`已拆解视频/`（或还没挪走的 `待拆解视频/`）里有参考片时，再运行一次 `frames.py <预览.mp4> --compare <参考片>`；还没有参考片时跳过这一步，并提醒用户把喜欢的视频放进 `待拆解视频/`。
   - 用看图工具打开 `hook_01.jpg`、每张 `sheet_*.jpg`、每张 `cues_*.jpg` 和对比图，真的看。卡词帧专门用来核对两件接触表看不出的事：画面有没有卡在词上，框和箭头有没有套住目标。
   - 运行 `audio.py report` 查响度和 BGM 大小，`audio.py sfx` 查每个音效听不听得到。
   - 按 visual-grammar.md 的自查清单（15 条）逐条写下结论和时间点，然后修改。
   - 通常一到两轮。两轮后还解决不了的，写清原因告诉用户。
2. **可选：请外人看**：有子代理工具时，可以请一个没参与制作的子代理，提示词按 `templates/review-agent.md` 写。只给它 BRIEF、画面标准、接触表、卡词帧和参考片对比图，不给你自己的结论，让它挑出最影响观看的三个问题。改完想再看一轮，另开一个新的。新的眼睛能看到做的人看不到的问题。这是加分项，不是必过的关卡。
3. **声音**：你听不到的部分，比如语气和混音平衡，如实告诉用户，请他试听判断。
4. **用户预览**：请用户看预览，用两三句话说这版改了什么、还有什么已知问题，然后按反馈修改。
5. **导出**：用户明确说“导出”才渲染成片 `exports/<主题>_v<N>_1080p.mp4`。
   - 导出后对成片再跑一次 `frames.py` 和 `audio.py report`，确认没有黑帧、字幕首尾完整、音轨都在。响度离 -14 LUFS 超过 1 dB 时，用 `audio.py normalize` 另存一个新版本号的文件。
   - 最后运行 `episode.py stage <项目> delivered`，并提醒用户：发布 3 天和 7 天后，把作品数据截图发过来复盘。

### 6. 发布后复盘

用户发来数据截图时，按 `guide/retro.md` 做：
1. 读出数字和留存曲线；
2. 用 `retention.py` 把掉人的地方对到镜头上；
3. 回去看那几个镜头，写下原因；
4. 按 `templates/retro-template.md` 写 `planning/RETRO.md`；
5. 在 `频道复盘.md` 里追加一行。

同一个规律在 2 期以上的复盘里都出现，才向用户提议改标准。

### 拆解用户喜欢的视频

用户发来或放进 `待拆解视频/` 的视频，按手法库 README 的“怎么长大”一节做：
1. 运行 `dissect.py <视频>`，得到接触表、逐秒图、节奏统计和转写；
2. 真的去看这些图，补上逐时间点的观察；
3. 把新手法写成卡，或者补进已有的卡；
4. 更新 INDEX。

不要替用户登录抖音或下载视频。请用户自己保存视频文件。

## 四、只在这些时候停下来问用户

- 本期三个决定：主持人、调性、素材路线。
- 样片方向（包括两版探索样片选哪版）。
- 需要用户听或看才能定的：角色声音选哪条候选、插画主持人设定图、混音听感。
- 需要用户动手的事：录屏、真人口播、生成 AI 视频并回传、补齐缺的输入文件、发布后的数据截图。
- 会产生费用的调用、改动口播原话、导出和发布。

除此之外的事都自己判断、直接做，并在 NOTES.md 记一句。比如选哪个组件、用什么转场、怎么调参数、修 bug、先做哪一章。用户说“你定”时，就按推荐做，并告诉他你选了什么。

## 五、用户反馈怎么处理

- **本期的反馈**：记进 `planning/NOTES.md`，改片，下一版自查时专门确认改到位了。
- **不要直接改成 skill 规则**：某一期的具体意见不写进 skill。同类意见或同一个数据规律在两期以上都出现时，再建议用户写进 `guide/style-profile.md`、`guide/visual-grammar.md` 的对应段落，或者写进手法卡。做法是改写那一段，而不是在末尾追加一条补丁。
- **为什么**：旧版就是每次返修都加一条规则，最后长到约 12 万字，模型忙着守规则，反而忘了把片子做好。
- **品牌包的改动**：样片或成片里被用户认可的版式改进，改进 brand-kit 的 `src/`，让以后每一期都受益。只属于这一期的调整，留在项目里。

## 六、交付

交付这些东西：
- 项目目录；
- 成片或样片；
- SRT / VTT 字幕；
- `ATTRIBUTION.md`（外部素材、音乐、音效的来源与署名）；
- NOTES.md 里的待办。

最后用一两句话说清完成了什么、还缺什么。
