# 整片动态多样性：先合适，再随机

用户希望同一视频的动画、动效、转场与音效有变化，同类型组件不要总是同一种出场。默认采用有约束的随机编排；本期明确选择和内容可读性优先。随机发生在策划/编排时，最终配置冻结；重播、seek、渲染不重新抽签。

## 什么该变，什么要稳

- 稳定：视觉系列、字体、字幕样式、语义颜色、旁白和操作真实性。BGM 按段落情绪安排，不随每镜随机换曲。
- 动画变化：同类组件可采用不同的入场、内部揭示顺序、关注位置、停留与退出。先区分组件专属的叙事动画与通用包装；不能为换动效抹掉专属动画的步骤或提前显示结果。候选不兼容就不要选。
- 图片/录屏变化：在素材允许的前提下轮换全貌→重点、细节→全貌、横移、焦点跳转、静止阅读及分屏说明。幅度变化不算新的动作家族；低清录屏和阅读段保持克制，不随机移动到无关位置。
- 转场变化：直接切镜是正常剪辑，可以连续使用。只在内容关系需要时选交叠、推移、遮罩或同主体衔接；左右推移属于同一家族，不能靠反向规避重复检查。装饰转场不连续轰炸，不凑种类或固定比例。
- 音效变化：先按点击、信息出现、强调、完成、转场等意义筛选，再换合适的音色。相同原始声音的不同预设算同一家族；同一按钮真实操作可保持一致。不要把错误音随机配成功，不给每个动作加声，静音是有效候选。保留正常语速与音高，不靠随机变速造“新音效”。
- 节奏变化：相邻镜头可在建立、行动、阅读、强调之间起伏。阅读停留从内容决定，不为了随机缩短；强调后优先留缓冲。

## 先建候选池，再编排

1. 从当前 director-index、实际 props 与可播放预览筛选本段可用候选。每种镜头有几种合适方案就用几种；只有一种可用时记录原因，不为多样性硬换。库不具备所需动作时明确“待扩展”，不要杜撰 ID 或能力。
2. 将不适合本段素材、清晰度、语义、风格、时长及动作目标的方案先排除。effect.exclusive、DOM 目标、专属时间节点及媒体时钟都需核对；同类别不等于可互换。同一 transform 层不叠加多个相机动画。
3. 按全片顺序记住已用动作家族、转场家族、声音家族和强调强度。同类组件优先避开上一次的动作；装饰转场和提示声优先避开前两个镜头刚用过的家族；避免连续强强调。还要避免固定 A→B→C 循环：工具对最近八镜中已经出现的相邻处理组合增加重复代价。这些是可解释的偏好，不是牺牲语义的硬禁令。必要重复写理由。
4. 合适程度相当、重复代价相同的方案再用固定 seed 随机选。项目 seed 用项目标识加版本，如 `本期目录名-variety-v1`；沿用已有值。用户要求“换一套”才更新版本；只调整某段时锁定其他已选项，不整片洗牌。
5. 把最终选项的真实配置写进原有分镜与场景 JSON，动作/声音落点用实际旁白时间。不把 helper 的标签当作可直接渲染的 API，也不让播放器接收随机指令。

## 与开场确认衔接

开场的“动画与转场”“音乐与音效”阶段，展示实际可播放、可试听的候选组合，让用户确认本期允许轮换的范围。已有“有变化/更有动感”等偏好沿用，不每镜重问。

在 `PROPOSAL.json.variation` 保存 `mode`（如 constrained）、`seed`、`policy`（简短中文说明）、`allowed_item_ids`（引用本提案已展示的 items）、`exceptions`（字符串说明列表）。候选在 items 中仍记录真实库 ID、预览及用途；背景、边框和音乐维持各自已确认选择。`opening_plan.py build` 会将 variation 展示在 PLAN 中，整个对象已受现有 proposal fingerprint 保护。

确认的是已展示的候选池与轮换规则；池内逐镜分配不要求逐镜确认。若用户已指定某镜具体效果则锁定，不因池存在而覆盖。池外新增、改变方向或已确认具体项，按现有规则更新完整方案并取得确认。允许轮换不等于自动获得新项目制作/导出授权。

确认前只做分段候选方案；不提前建 EDIT 镜头。确认后把实际选择放 `EDIT.scenes[].motion_choice`，写选项 ID、家族、seed、配置引用及必要的重复理由；实际时长仍来自 EDIT，实际参数仍来自场景 JSON。它是选择元数据，不是第二条时间轴。旧工程不批量迁移。

## 可复用的选择工具

原始 `scripts/motion_variation.py 输入.json --out 新输出.json` 仍只在编导已经筛好的候选中选方案，不自动检索、推断兼容性、确认方案或改写工程；它不会验证 payload 指向的场景。实际要把候选用于组件镜头时优先用 `library_prepare.py vary --pool pool.json --out selection.json`：它先对每个 `payload.config` 调库的严格场景校验，再复用同一个 `select_variations` 算法，输出保留 payload、配置哈希、库 revision、输入哈希、使用统计与重复提示，已有输出不覆盖。

输入为 `{seed, units:[{id, component_type, options, locked?, repeat_reason?}]}`，按分段/镜头顺序排列。`component_type` 是需一起比较的内容类别（例如录屏、对比图解），不要用独特镜头 ID 绕过同类重复检测。

每个 option 包含：

- `id`：编导自定义候选编号，不冒充库 ID。
- `motion_family / transition_family / sound_family`：听看后归类的家族标签；静止用 `still`、直接切镜用 `cut`、不转场用 `none`、安静用 `silence`。它们可重复，不被机械去重。
- `energy`：quiet / normal / accent；`weight` 为正数，默认 1，仅用于重复代价相同方案之间的加权抽选。
- `payload`：该候选的实际场景配置或配置引用与父工程处理说明；使用 `library_prepare.py vary` 时必须包含 `config`，且文件位于 pool 所在目录或其子目录。助手仍需要把它落实到现有接口，工具不假装已经应用。
- `locked` 写该单元的 option.id，可保留用户指定或已实现镜头；即使重复仍保留并提示。锁定候选若不能通过严格场景校验必须报错；无合适候选也报错，不从全库随便补一个。

`vary` 的验证覆盖配置契约和已知本地素材，不等于视觉审片、素材许可核实或 proposal 确认。`compatibleEffects`、实际预览和本期确认池仍由编导负责；只换 seed 会产生另一组确定性规划选择，播放器和正式渲染不会在运行时重新随机。

## 验收

动态轮换与文字框的视觉身份分开管理。标题、对象、动作、结论等同一语义等级全片固定同款；不要为了避重复去轮换其形状。方向箭头按实际方向/geometry筛候选再确定性选取，不把无头括线计作一种箭头。具体入口见 [方向箭头与语义标注](semantic-annotations.md)。

整片审片除逐镜正确性外，还要连续播放检查重复疲劳：相似运动家族是否频繁出现、同类组件是否总同样出场、提示声是否连续撞音、强弱是否有停顿。检查工具统计只提供线索，不能用“用了多少种特效”判合格。

实际选择须处于已确认候选范围；同一种声音不同文件名、同一种推移不同方向不算充分多样。锁定后重播/倒序 seek/导出保持相同结果；更换动效后复查前后镜头、阅读时间和声音节点。此 helper 不会自动增加动效或音效资产；素材池不够时，先明确具体缺的表达能力再扩库。
