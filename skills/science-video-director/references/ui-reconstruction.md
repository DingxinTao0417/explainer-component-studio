# 观察真实软件后复刻组件

用于用户选择可编辑界面组件来模拟软件工作的情况，尤其需要控制中文、表格、回答节奏或镜头焦点时。这是明确的制作路线，不要求用户为同一镜头再录屏；仍需真实能力或实际结果证据的段落单独实录。

## 先观察，再决定复刻范围

- 用可用的电脑操控工具观察目标软件，记录应用、平台、网页入口或桌面版本、核对日期和覆盖状态；读不到版本就保留未知。旧截图或另一平台只能补充，不能冒充本轮当前观察。
- 先分清产品与模式，例如普通“豆包”的对话模式与“豆包工作”应分别建组件，不能沿用相似名称当成同一界面。桌面观察工具失败时，可说明限制并以官方网页补充实现；明确网页来源和桌面待核对项，不能写成桌面实测。
- 重点看本片要用到的输入、提交、运行、回复、附件、文件或结果预览，以及消息滚动、按钮变化和面板位置。只看过空白首页，就不声称已核实完整工作过程。
- 观察 UI 和执行任务分开。按用户授权进行必要的演示操作；未经授权不发送其他会话内容、不动已有草稿或文件。若只读观察即可支撑所需外观，不为取得假设结果强行执行。
- 实际输出与稿件假设不一致时照实记录。例如真实回答主动追问或留占位，不能说它产生了稿件里那条含糊回答。后者可以继续作为标明“案例演示”的假设内容。

## 复刻成可用组件

优先扩展已有库，把应用外壳、输入区、消息、运行状态、附件和文件预览拆为可编辑对象；复用准确的品牌资产，不用 AI 重绘软件文字或整张截图伪装可编辑实现。

按本片需要提供内容参数和状态：多轮消息、输入草稿、发送/停止、运行/完成、表格行与计入状态、可选预览面板。状态数量由实际讲解决定，不强制每次还原整个应用。精确文字与数据来自传入内容，动画时序由成片配音控制。

在画面适当位置标明“界面复刻 · 案例演示”或同等清楚的说明。教学表格、统计摘要等应说明是展示内容；未经观察不得暗示软件有某个原生专用面板。不能将作者填写的模拟回复、等待时长、命令日志或数值包装为实际运行输出。

## 留痕与验收

在本期计划记录 `观察依据 → 已覆盖状态 → 组件及实现路径 → 模拟内容来源 → 尚未核对项`。将原录屏要求标为已被替代并保留历史；没有实视频就不标 acquired。来源类型和台账沿用 [项目契约](project-contract.md)，不要再建立冲突时间轴。

先做足以代表实际用法的一段动态流程，再按需复用：文字/数据可替换，应用比例正确，主对象不随背景漂移，输入和结果先后关系清楚，字幕不挡关键区域，倒序 seek 后仍能恢复正确状态。显示准确度按证据范围描述；局部观察或一个截图不支持宣称所有版本、面板和交互已 1:1。

只有在“本次真实执行了什么、软件实际能否完成、输出是否正确”本身就是影片论据时，才要求对应的真实操作或结果证据。组件模拟可以解释步骤与思路，不能替代这类证明。
