# 录屏操作脚本

仅用于本期仍有效的实录需求。用户选择“观察真实 UI 后用组件模拟”时按 [观察与界面复刻](ui-reconstruction.md) 执行，取消对应的用户待录要求；不要一边接受替代方案，一边继续把同一录屏列为交付阻塞。

录屏要让观众看清操作与结果。每个录屏任务用稳定编号 `R001`，关联分镜和配音时间；一个长录屏可供多个镜头使用。

在 `RECORDING_PLAN.md` 给用户可执行的任务卡，`RECORDINGS.json` 保存状态和文件映射：

| 项目 | 必须具体到什么 |
|---|---|
| 目的与旁白 | 本段证明什么、对应原句及最终时间段 |
| 环境与准备 | 软件/网页地址、版本或核对日期、窗口尺寸、演示账号、数据/文件、是否需要网络；不在稿里要求用户分享密码 |
| 起始画面 | 从哪个页面、哪个标签开始，哪些无关窗口/通知收起 |
| 操作顺序 | 每行一个动作，准确入口、目标、点击/输入/快捷键、可复制文本和预期界面结果 |
| 节奏 | 点击前的停留、结果出来后的停留、鼠标落点、何处全景/局部特写 |
| 剪辑 | 原始操作耗时与最终使用长度分开；等待可剪掉或明确加速，重要步骤不能消失 |
| 素材输出 | 文件名 `R001_take01.mp4`，存至本期 `input/recordings/`；建议与成片一致的清晰画幅，不拉伸文字 |
| 失败与补录 | 入口变化、结果没出现、网络慢时的替代路径或单独补录段落 |

每个步骤建议使用这组列：`序号 | 当前画面 | 操作/输入 | 预期结果 | 停留/鼠标 | 对应配音/剪辑点`。复杂输入落为项目内文本文件，用户可直接复制，不用从截图抄写。

检查当前真实界面或官方文档。任务级记录 `observed` / `documented` / `unverified` 和证据；没有实际演练就明确预期结果尚待录制验证。网页内容或软件版本变动后重新核对，不凭记忆编造按钮。

默认预留约 1–2 秒起止静止画面供剪辑，具体按动作调整。重要操作应在最后1080p画面上可读；必要时录较高分辨率供裁切推近。隐藏通知、敏感目录和账号信息，保留完成任务所需的真实 UI。

用户尚未录制时状态为 `planned`，采用文件为空。原始文件送回后先探测参数、观看并标出采用区间；通过后 `status: acquired`、`reviewed: true`，关联素材 ID。文字计划、静态模拟或生成的操作动画都不能标记为“录屏已完成”。
