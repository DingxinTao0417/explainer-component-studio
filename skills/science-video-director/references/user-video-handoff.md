# 用户生成视频素材交接

适用于用户希望助手完成编导、参考图流程与提示词，再自行用视频模型生成并回传的工作方式。本用户已确认视频继续由本人生成；生图按 [三项输入、风格参考与生成能力](design-and-generation.md) 有能力直接生成、无能力交详细提示词。本期明确决定优先。只更新 skill 时不生成图片或视频，不启动整期制作。

## 流程与停止点

SRT/音频/design 齐备 → 编导与素材分工 → 用户风格参考 → 生图能力判断 → 直接生图或交提示词等图片回传 → 检查参考图/共享环境图 → 交付逐镜详细视频提示词 → **等用户生成视频回传** → 检查实际视频 → 合成 → 全片独立审查 → 预览选择 → 导出决定。

- `user_handoff` 只改变 AI 视频素材的生产与交接；助手仍负责已授权的参考图流程、Pexels 素材、组件、配音和后续合成。图像工具不可用时交详细生图包而非伪造成图。静态图或组件足以表达时直接使用，不人为增加 AI 视频任务。
- 参考图与交接包完成前继续处理本阶段必要工作；完成后结束当前制作轮次，给出实际文件链接、回传位置和剩余镜头。停止派发后续依赖这些视频的制作/整合任务；正在执行的相关任务收尾保存后进入等待，不让子代理绕过节点继续交整片。
- 这次停止是等待用户选择亲自生产的素材，不是索取新的生成或预览许可。不另问“是否允许我停下”，不自动轮询文件夹或设置后台监控。用户回传或明确让继续检查时再接续。
- 已有视频直接检查，无新缺口则跳过交接。用户明确改由助手生成时才改为 `agent_generate`；不把“继续”“导出”或未回复解释为变更。目标平台未定时可以完成参考图和通用动作提示词，平台专属参数标待适配，不能虚构模型能力。

## 先完成能直接使用的包

1. **编导与分工。** 每镜关联唯一 `EDIT.json` 的镜头 ID、对应旁白、理解目标、时间区间，确定组件/实拍/录屏/生成路线。复杂动作拆成自然的短镜头，分别设计初态、主动作、终态及连接；不按参考片的剪辑段数机械决定生成次数。
2. **风格、能力与参考图金样。** 先取得或明确用户的生图风格参考，读取当前 `imagegen` 并检查可调用工具。有能力时按 image2 路线生成一幅代表图，实际查看构图、风格、主体身份、初态和安全区，再展开同类图；无能力时完成同等详细的生图提示词及回传清单，等用户生图后核对。参考片的方法可借鉴，色板、材质和人物规格仍按 design，不自动照搬多种画风。已有明确画风不重复索取确认。
3. **逐镜与环境参考图。** 图生视频用最终画幅的独立完整场景，角色/道具保持一致；同环境多镜先按 [环境参考规则](design-and-generation.md#相同环境先做环境参考图) 生成独立 ENV 图或交环境生图任务，各镜共用布局、机位基准和光源。拼图与接触表仅作说明，不当首帧。每张标明风格、身份、环境、构图、首帧或终态职责。需要且平台支持时提供尾帧；不把终态图声称为已生效约束。透明 PNG 用于独立元素，不能假设生成视频具有 alpha。
4. **写详细视频提示词。** 按 [逐层动作规范](design-and-generation.md#视频提示词必须逐层逐对象逐时段) 覆盖所有重要对象的初态、动作或静止、起止位置、速度/先后、接触/遮挡、机位与运镜、光影与环境变化、结果停留及衔接；提供动作表和完整可复制文本。参考图未回传时仅为待图核对草稿；实际图齐备后核对再交可用版本。H3 才使用六字段，其他平台不套其帧网格或 Budget 参数；细节必须能在时长内完成，不以同时增加动作代替详细说明。
5. **明确合成责任。** 字幕、精确数字、软件界面与品牌标记优先由后期/组件处理。运动物体上的文字后期添加时须规划跟踪和遮挡，不承诺静态贴字能跟随任意 AI 动作。生成视频默认不承担旁白和配乐；未知后端是否产声时记录回收后处理，不把提示词静音说成实际已关闭音频。
6. **写用时与回传说明。** 区分成片所需时长、建议生成时长和动作前后停留；有配音用实测时间，缺配音则明确估算。实际采用区间在看过回传视频后填写，不预造时间码；不加速或截断原配音来凑视频长度。保留用于转场的余量，但按本镜需要选择，不强加统一秒数。

每镜最小交付内容：

| 产物 | 内容与验收 |
| --- | --- |
| 镜头卡 | 镜头 ID、旁白、讲解目标、画面职责、与前后镜头的接口；用时引用 EDIT |
| 参考图或生图交接包 | 有能力时交已查看的独立图片、尺寸、职责、版本和 SHA-256；无能力时交详细生图提示词/参考绑定/回传规格，明确待图状态；共享场景含独立环境图任务 |
| 视频提示词 | 完整逐对象/分时段动作、运镜、环境变化与终态说明；和实际图相符，只用目标平台支持的功能；图未回传明确为待图核对草稿 |
| 生成说明 | 建议生成长度、最终所需区间长度、稳定停留与裁切留白、声音约定、平台参数适配状态 |
| 回传清单 | 逐镜文件名、绝对保存目录、多个 take 命名方式、对应镜头和验收重点 |

图片工具不可用或失败时，完成详细生图提示词及待图核对的视频提示词，真实标记“提示词交接完成、参考图待回传”；不能把草稿、空文件或占位图标为“参考图交付完成”。用户回传图后检查风格/环境/初态并修订视频提示词，才进入待视频回传。已完成的其他镜头保留，不重复无关生成。

## 项目内记录与版本

沿用 [项目契约](project-contract.md)，不创建第二份时间轴或并行的 PRODUCTION.json：

```text
planning/AI_VIDEO_HANDOFF.md                用户操作与回传总单，时间从 EDIT 派生
generated/<shot_id>/handoff-v1/
  reference-start.png                     实际图像格式为准
  reference-end.png                       仅在确实需要并生成时存在
  image-prompt.txt
  video-prompt.txt
  shot-card.md
generated/environments/<env_id>/            同环境镜头共用的环境图/提示词，按需创建
assets/images/inbox/                       无生图能力时用户回传的图像
assets/video/inbox/<shot_id>_v1_take01.mp4  用户回传后才存在
qa/ai-video/<shot_id>_v1_take01.md          实际回收检查与采用/补生成理由
```

- `PROJECT.settings.ai_video_mode` 为 `user_handoff` 或 `agent_generate`。总编导读取本期决定，旧项目只按需补充，保留已明确的生成方式；初始化写默认偏好不等于自动生成了交接包。
- 需要交接时才添加 `PROJECT.generation.user_handoff`：`{status, version, guide_file}`。status 使用 `preparing / awaiting_style_reference / awaiting_images / awaiting_user / reviewing_returns / needs_regeneration / complete`；awaiting_user 专指参考图已核对、等用户回传视频，awaiting_images 专指无生图能力/缺图待回传。`guide_file` 为真实说明路径，没有文件留 null。无新缺口不创建虚构任务。complete 仅代表生成素材回收验收，不代表全片审查通过。
- `EDIT.scenes[].asset_ids` 引用拟采用视频的 ASSETS 项。待生成时 `kind: video, origin: generated, selected: true, status: planned, file: null, sha256: null, reviewed: false`；镜头仍为 draft，有占位时保持 placeholder=true。参考图片单独登记为 image，不能用图片路径顶替 video 文件。
- 在该视频资产上加 `generation_handoff` 元信息：镜头 ID、交接版本、风格/环境/主体参考职责、实际参考图路径及哈希、提示词路径及哈希、目标平台或 unknown、预期回传文件名。无实际图时路径/哈希留 null，期望文件名单独写，不伪造文件存在。本期取用时长由 EDIT 派生；用户制作仍标 generated，可用 provided_by:user 记录回传者。
- 版本更新保留旧图/提示词和 take。影响动作、构图或时序的修改要同步交接卡并说明旧版是否仍能用；只看文件名不能判定素材匹配。没有用户提供的模型、参数、seed 或任务 ID 就记未知，不伪造 Agent 提交记录。
- TEAM 记录当前阻塞在什么镜头、已交付包、已接收素材和下一步；待回传列表从当前采用资产派生。不要靠 selected=false、改成 graphic 或空白占位绕过未完成需求。

这些新增交接字段是流程元信息；现有 `episode.py check` 不自动审核包、图片内容或提示词语义。交接阶段运行 `--phase plan` 保留待办并人工核对以上真实产物，不把完整制作的 `ready` 失败当作需要新权限；也不把 plan 通过称为素材或全片已就绪。

## 回传检查与接续

1. 对照当前交接版本与镜头 ID 接收实际文件，保留原 take，记录来源路径、项目内路径与哈希。无法可靠判断对应关系时只问必要的映射信息，不按文件名盲猜。
2. 探测真实时长、尺寸、帧率、可解码性和音轨；实际查看从初态、动作到终态，核对身份/数量/方向、角色与文字形变、风格、裁切、留白和动作表达。重要衔接要在相邻镜头中试接。听过才称试听；默认合成不采用生成旁白/BGM，不自动混入未知音轨。
3. 合格后将 ASSETS 标为 acquired/reviewed，填写实际采用源区间、哈希、生成来源与适用使用依据。下载/回传本身不等于通过；失败候选保留为未采用，当前所需资产仍显示待补，给时间点、具体缺陷与修改后的参考/提示词说明。
4. 只回传部分时核对并登记已到项，保留待回传/needs_regeneration 清单；不自动生成剩余镜头，不宣布交接完成。用户明确要求局部草稿时可制作并标明缺片；否则停在剩余素材依赖处。
5. 所需视频齐备且检查合格后，将交接状态设为 complete，沿用 EDIT 继续组合组件、字幕、背景、声音和转场。只能通过剪辑实际素材或明确的镜头调整解决时长差异；改变用户口播需已有相应授权。然后按正常 ready → 冻结 → 独立审片 → 用户预览/导出流程执行。

参考图自检、回传素材检查和最终独立审片是三种不同结论。不能用“参考图通过”证明运动稳定，或把素材验收当成全片已通过。
