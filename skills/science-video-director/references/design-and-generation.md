# 三项输入、风格参考与生成能力分支

本用户的整期视频制作入口使用 **SRT、对应音频文件、design.md**。本规则不要求只讨论、写稿、制作 design 或更新 skill 的任务先提供全部媒体。

## 接收与 design.md 的作用

- 先检查已附文件、用户指定目录和当前项目，建立各段 SRT 与音频的对应关系。缺失哪一项就集中请用户补该项，不重复索取已有材料；“音频文件”指可解码的音频，不是音频文字说明。
- `design.md` 描述本期主旨/受众、剧情与易误解之处、画幅/色板/字体、视觉参考职责、组件和生成素材分工、镜头组与动作原则、声音/字幕、交接及验收。它不能代替实际音频，也不维护另一套正式时间轴。
- 按 [镜头分层](scene-composition.md) 写清讲解、软件演示、实拍及标题卡各自的背景/外框策略，记录已确认样板、Logo、主体比例与字幕安排。用户修改某类镜头时同步其例外，不用一套全局外框覆盖所有场景；已批准的预览图作为实现对照。
- 用户没有 design 时，先提出可根据现有材料代拟；用户已要求代拟就直接完成，缺少的实质决定单独标待确认。助手代拟 design 时以已确认的 [开场策划案](opening-plan.md) 为准（组件、背景、边框、音效、音乐与风格系列），不另立一套外观。三项未齐可完成理解、设计草稿和素材清单，不能宣称进入素材齐备的整片制作。只有用户明确让助手生成缺少的音频/字幕时才走相应生成/对齐流程，不将历史 Qwen 默认音色当作替代用户交音频的授权。
- 保存原始输入及哈希，工作版放项目根 `design.md`。导入后按 PROJECT.inputs 的原文件名与路径映射，更新工作版中的媒体相对链接，使其指向已复制的项目内文件；原 design 保持不变，不让渲染依赖源目录。后续变更记录在本期编排中并同步到 HyperFrames 所消费的版本；存在旧 `frame.md` 或 `DESIGN.md` 时检查优先级与冲突，不能让旧文件悄悄覆盖本期 design，也不直接删除用户文件。
- 多段 SRT 若各自从零起算，按实际配音剪辑映射累加偏移并重新编号，不能拿上一段最后一条字幕结束时间代替音频片段长度。有差异需试听核对；未听过不写已同步通过。

## 生图前先明确用户的风格参考

1. 实际生图前先索取生图风格参考图片。若用户已提供且明确指定用途，直接读取并复用，不重复上传或确认；现有图片仅是剧情板/素材总览、用途尚不清楚时，简短确认它是否也作为生图画风依据，或请用户补充其他风格图。
2. 记录每张参考用于画风、角色身份、物件造型、环境、构图、首帧还是终态，区分“借画风”和“保留对象”。缺参考或未确定用途时可完成结构策划，但不要擅自选一种画风批量生图；用户明确授权无参考自由设计时记录这一选择。
3. 风格用可执行描述落实：线条与轮廓、平面/体积感、材质、色板、阴影、光源、角色比例、背景细节和字幕留白。与 design、组件库和前后镜头对照，不能只写“高级、精美、同款”。

## 判断当前 Agent 是否真的能生图

检查当前可调用工具及实际支持的输入，而不是仅看是否装有名为 imagegen 的 skill。读取 `imagegen` 后按其可用入口执行；能生成、能编辑/引用图片、能输出透明通道分别核实。本用户偏好 image2，实际模型名称按入口报告，未暴露则写未知。

- **能力可用、风格已明确**：直接生成本任务已要求的图片，先检查代表图再展开，不再把已授权制图变成一次“是否生成”的许可问题。支持参考输入时将已查看的参考实际附给工具，而不只在提示词里声称“参考了”。
- **没有可用生图能力或调用不可用**：完成详细生图提示词与交付规格，交给用户在其他工具生成。列出需要附哪些风格/角色/环境参考、提示词对应哪个镜头、返回文件名与存放位置。不能以伪图、现有缩略图或占位代码充当生成结果，也不自动购买服务、注册账户或切换未授权 API。
- 图片尚未回传时可写详细视频动作草稿，但明确“待参考图核对”；收到实际图后检查对象、位置与初态，修正动作提示词，才标可用于图生视频。纯文字写完只能称“提示词包完成”，不能称“图片已生成”。

每张生图提示词写清：用途/参考职责、画幅和交付格式、景别/视角、前中后景、每个主要对象的数量/形状/比例/位置/朝向/遮挡、环境结构/材质/色彩/光影、准确初态、字幕安全区、需要保留与不出现的内容。精确文字、数据和品牌标记优先留给组件；不把多阶段动作塞进一张首帧图。透明元素、完整首帧、环境底图分开出任务。

## 相同环境先做环境参考图

连续或多镜头共用同一场景/背景时，先建立独立 `ENV-xx` 环境参考图：固定布局、地平线、地面/墙体、门窗/道路、稳定道具、光源、色彩和材质。动态角色、车辆、待搬货物等另作对象参考或留出位置，避免烘焙进底图后每镜重复增生；场景确需固定道具则明确其身份。

环境图也走“用户风格参考 → 能力判断 → 直接生图或详细提示词交接”流程。一份实际环境图供同组镜头引用，记录其版本、路径、哈希和朝向。机位变化仍保持同一空间结构；透视变了不能凭空换门窗。采用首尾帧或多参考约束前核对平台能力；只支持单首帧时，把环境与主体合成适用的完整首帧，不硬塞拼图。

组件库的网格等程序背景继续使用可编辑组件，不为凑“环境参考”生一张无用途的网格图片。需要图生视频的共享环境必须提供独立环境图或对应待生图任务，不能只写一句“背景不变”。

## 视频提示词必须逐层、逐对象、逐时段

视频仍默认由用户生成并回传。先完成上面的参考图流程，然后按 [用户视频交接](user-video-handoff.md) 写可复制的完整提示词；复杂镜头同时提供便于核对的动作表，不能只交表不给提示词。

| 字段 | 写到什么程度 |
| --- | --- |
| 参考绑定 | 镜头/环境/角色 ID，实际参考图及职责；平台不支持的约束不伪称生效 |
| 初始画面 | 镜头开始时所有主要对象在哪、朝哪、什么状态，与实际首帧一致 |
| 对象动作 | 对每个主要可见对象/图层分别写动作或保持静止：谁先动、如何移动/转向/接触/释放、路径、相对速度、终点、遮挡与消失依据 |
| 时间阶段 | 以本镜相对时间或明确先后关系拆“建立→动作→结果停留”；各动作能在计划时长内完成，时间段不互相矛盾 |
| 运镜 | 景别、机位/高度/朝向、推拉摇移或固定、起止构图、速度/缓动、焦点/景深；区分相机移动与物体自己移动 |
| 环境变化 | 地面/背景/固定道具是否静止；光线、投影、反射、尘土、蒸汽等是否变化及触发原因。不需要的变化明确保持稳定，不为丰富而全屏同时动 |
| 终态与衔接 | 哪些对象留在画面、各自最终位置和状态、结果停留、下一镜从什么状态接入；首尾不突然重置 |
| 后期分工 | 哪些标题、字幕、箭头、数据和声音由合成添加；需要跟踪/遮挡时给可执行安排，不靠生成模型拼写事实 |
| 约束与验收 | 数量/身份/方向/因果不变，不凭空复制或消失、不换画风；写与本镜相关的失败表现，避免无关负面词堆砌 |

“每个部分”覆盖所有重要对象、环境层和机位，静止对象也要说明；不把每个像素写成动作，也不因文字详细就安排过多同时发生的事件。复杂因果或模型难稳定完成的动作拆镜，用共同环境和终态交接保持连续。提示词细节是目标，不是对生成结果逐帧精确可控的保证。

未知目标平台时提供通用完整版本及“参数待适配”；确认后再映射其支持的时长、参考图数量、提示词长度和音频选项。图像未生成/环境参考缺失时，视频包保留待参考状态，不自动越过等待环节。
