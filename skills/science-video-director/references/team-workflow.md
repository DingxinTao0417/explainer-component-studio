# 三角色协作与交接

整期制作或多镜头续作时读取。目标是统一创作方向、减少制作盲点；不以 Agent 数量衡量质量。只修改 skill 时不启动媒体制作。

## 分工与权威文件

| 角色 | 决策与产物 | 写入边界 |
| --- | --- | --- |
| 总编导（当前主助手） | 用户决定、开场策划、主线、分镜、金样、任务分配、整合和最终交付 | `PROJECT.json`、`planning/PLAN.md`、`planning/PROPOSAL.json`、`planning/EDIT.json`、共享素材/字幕台账、顶层合成和跨镜头转场 |
| 制作 Agent | 按任务包制作镜头、音画处理和定向返修；使用 [制作角色](roles/producer.md) | 只写任务包列出的镜头、素材目录和交接记录；共享文件修改作为建议返回 |
| 独立审片 Agent | 根据原始要求实际看画面、看动态、听声音；使用 [审片角色](roles/reviewer.md) | 只写当前版本的 QA 证据与审查报告；不同时改制作文件 |

`EDIT.json` 始终是唯一时间轴。HyperFrames 的 `STORYBOARD.md` / `BRIEF.md`、镜头任务包和 motion sidecar 从它与本期编排派生；发现冲突先由总编导更新权威记录，再同步派生文件。不要让不同角色各自保留一条时间轴。

`planning/DIRECTING.md` 放编导决定与风格依据；协作进度、Agent 实际 ID、任务归属、问题状态、预览/导出决定记在 `planning/TEAM.md`。角色 ID 使用工具真实返回值，不用“审片员”这个显示名称冒充独立身份。旧项目不重建、不批量迁移，接续时按需增加协作记录并把后续进度写入 TEAM。

## 调度顺序

先检查 SRT/音频/design，按 [风格与能力规则](design-and-generation.md) 取得生图风格参考并判断当前制作 Agent 的实际能力。有新 AI 视频且采用 user_handoff 时，编导方向确定后执行 [用户素材交接](user-video-handoff.md)：有生图能力交实际参考图/同环境图与详细视频提示词，无能力先交详细生图包并等图回传，核对后完善视频提示词。总编导交付后停止后续依赖任务，等待对应素材。图像金样不等于动态金样；视频回传检查合格后再制作与整合。无新视频缺口或明确采用 agent_generate 时按正常顺序执行。

1. **开场策划并取得用户确认。** 总编导读用户要求、参考与已有项目，按 [开场策划与用户确认](opening-plan.md) 出候选方案：讲什么、整体视觉、逐段组件/背景/边框/音效/音乐，附实际截图、试听文件和画廊链接，写清待用户拍板的问题，然后停下等回复。未确认前不写编导稿、分镜稿，不派制作任务包。用户改选后更新提案重新确认。
2. **确认后落成编导稿与分镜。** 把已确认的选择写进 design、DIRECTING 和 EDIT 时间轴，明确讲解目标、真实/模拟身份、镜头组与统一风格。由总编导统一解决用户选择和授权，子代理不重复向用户询问。
3. **金样。** 向制作 Agent 发一份有代表性的有限任务包，覆盖最不确定的正文画面与声音。总编导对照已确认方案与已有规范实际检查；用户已锁定风格时不额外加批准环节。金样作为后续制作参照，不充当全片审片。
4. **批量制作。** 默认一位制作 Agent 连续处理相关镜头。大量独立镜头可分包，每包写清初态、动作、终态和文件归属，留出审片并发位置；不按每镜一个 Agent 机械拆分。素材已就绪、共享依赖已固定后才并行。
5. **总编导整合。** 审核交接产物，把被接受的媒体、字幕、时长变化合入权威台账与主工程，运行 ready 和 HyperFrames 检查。子代理说完成不等于已合入。
6. **冻结并独立审片。** 制作写入暂停，运行 `review_gate.py freeze`。启用未参加该版制作的审片 Agent，使用最小上下文或不继承制作对话的委派方式。交给它原始要求、参考、已确认策划案、时间轴、冻结文件及实际工程，不把“制作方已通过”等结论当作审片依据。首次审查不提示希望它得出什么结论。
7. **返修。** 总编导将发现的问题分配回原制作任务；审片 Agent 不边改边审。返修后重新整合并冻结新版本，再由独立审片者复查问题点、相邻转场及受影响的声音/字幕。上一版未关闭问题须逐条给出新证据；不可由制作方自行标成已验收。
8. **交付。** 当前版 review 检查通过后，执行既有“预览选择 → 导出决定”流程。渲染后独立审看实际导出文件，将其路径与 SHA-256 写入该版审查记录；源码审查与最终文件验收分别记录。

同一问题连续两轮返修没有改善时，先重新定位原因或改变实现方法，不照旧无限重做。涉及未授权费用、改变讲稿或审美取舍才向用户集中说明；仍继续可完成的独立工作。

## 两类任务包

任务包保存在 `planning/tasks/<task-id>.md`，包含下列实际信息，不能只有角色名和“请完成”：

- **共同输入**：项目绝对路径、用户当前请求及约束、适用角色文件、权威计划/风格/参考路径、输入版本、实际工具和授权范围。
- 涉及 AI 视频时注明 `ai_video_mode`、当前交接版本和停止点；user_handoff 的参考图任务允许 imagegen，不包含视频模型提交或替用户补生成。
- **制作包**：镜头 ID 与旁白区间、初态/动作/终态、采用组件/媒体、必要文字与字幕留白、前后镜头接口、可写路径、禁止写入的共享路径、验收点和交接文件名。
- 多镜头制作包还引用 DIRECTING 的组 ID、理解任务与观看顺序，写清前后镜头的实际切法/触发点及声音任务；选用的方法 ID 仅作索引，不代替动作描述。跨包连接由总编导统一约定。
- **审片包**：当前 revision 与 snapshot 指纹、工程入口/可播放地址、参考和用户要求、预期镜头列表、可用查看/试听工具、QA 输出路径。复查另附既有问题及变更范围，不先宣布问题已修好。

可用当前环境的 `collaboration.spawn_agent` / `send_message` / `followup_task` 或等效委派接口；不要通过 `create_thread` 建用户侧任务。等待并读取完成产物后再整合，不只依赖任务状态。当前并发上限按工具实际能力执行。

专业方法继续按需读取已有 skill：前期编导、imagegen、H3、HyperFrames/core/animation/audio/cli 等。进入 HyperFrames 的多镜头分包时沿用其包和 sidecar 契约，由总编导统一派工；制作子代理不要再次扩张团队。角色文件是委派指令，不是要注册一批同名 skill 或修改全局 Agent 配置。

## 无法独立委派时

若环境没有可用委派能力，或用户明确要求只用一个 Agent，继续制作及单人自审，记录 `mode: self_review` 和原因，不伪造另一个 Agent ID。自审检查可记录通过，但默认独立审查门不会把它计为独立通过；先完成所有可做工作，交付真实状态。用户明确接受自审替代时，记录其原话与范围后，使用 `--allow-self-review` 检查并在交付中披露；已有明确决定不重复确认。单纯未回复或资源等待不能算用户接受。

用户明确要求只用一个 Agent 完成制作和检查，已覆盖该范围内的自审选择，直接记录原话并执行，不再重复询问是否接受同一分工。只有环境能力缺失、用户还没有作出替代选择时，才说明缺口并请求必要决定；不把脚本检查失败本身当成新增审批理由。

用户明确要求只修一处时，总编导可直接改动，再派独立审片者定向复核受影响镜头及相邻转场；不为此重新做全片策划或启动多个制作 Agent。
