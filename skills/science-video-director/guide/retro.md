# 复盘：发布后用数据改下一期

用户发来某一期的发布数据（通常是截图）时读。目的是让下一期比这一期好：找出观众在哪一秒离开、为什么离开，再把反复出现的规律沉淀下来。

## 1. 收数据

- **要什么**：请用户在作品发布 3 天和 7 天后，各截一次图发过来：
  - **抖音创作者服务中心 → 作品数据**：播放量、完播率、平均播放时长、2 秒跳出率（或 5 秒完播率）、点赞、评论、收藏、转发、涨粉，以及**观众留存曲线**；
  - **B 站**：播放、平均观看进度、留存曲线。
  - 能导出表格的，直接给表格。
- **读截图**：
  - 读出每个数字，写进 `planning/RETRO.md` 的数据表。
  - 留存曲线目测读点：开头 0–10 秒每 1 秒读一个点，之后每 5% 时长读一个点，另外在每个明显拐点处补读一个。存成 `planning/retention_points.csv`，每行“时间,留存%”。横轴是百分比时加 `--percent`。
  - 所有读图得来的数据都标“目测读图”。截图上看不清的，写“看不清”，不要猜。
- **不要登录用户的账号去抓数据**。只用用户发来的截图和表格。

## 2. 对到镜头上

```powershell
python -X utf8 <skill>/scripts/retention.py --points planning/retention_points.csv --edit planning/EDIT.json --out planning/RETRO_留存.md
```

它会给出：

- 3、5、8 秒处的留存；
- 25%、50%、75% 时长处的留存；
- 掉得最快的 5 段，分别对应哪些镜头；
- 钩子之后，第一个掉得比平均快的镜头。

然后**真的回去看那几个镜头**。用 `frames.py` 对成片的那一段抽帧，一个一个写下原因：

- 画面在那一刻是不是静了太久？
- 是不是同一类画面连续太长？
- 是不是字太小、信息太密？
- 是不是旁白在绕圈子？
- 是不是承诺的结果迟迟不出现？

原因写成“哪一秒、什么画面、为什么掉”，不写“节奏有点慢”这种空话。

## 3. 写复盘

按 `templates/retro-template.md` 写 `planning/RETRO.md`，一页以内：

- **数据表**：本期数字，以及和频道中位数的对比。
- **掉人的地方**：最多 3 处，每处写清时间、镜头、原因、下次怎么改。
- **留住人的地方**：最多 3 处。留存平台、或者评论里被提到的时刻，对应的是哪个手法卡、哪个惊喜时刻。
- **评论里的信号**：用户截了评论的话，摘出观众问得最多的问题和最喜欢的地方。
- **下一期试什么**：1–2 条可以验证的改动，比如“钩子第一帧换成成品，看 3 秒留存能不能从 62% 升到 70%”。

然后在 `<工作区>/频道复盘.md` 的总表末尾追加一行，没有这个文件就按模板里的表头新建。

## 4. 规律怎么升级成规则

- **单期的发现不改 skill**，只写进这期的 RETRO.md，下一期写 BRIEF 时读一遍。
- **同一个规律在 2 期以上的复盘里都出现**时，向用户提议升级，按规律的性质写到下面对应的位置：
  - **画面标准**：改写 `guide/visual-grammar.md` 的对应段落；
  - **用户偏好**：改写 `guide/style-profile.md`；
  - **某个手法好用或不好用**：在手法卡的“来源”行加“复盘：<期名> 3 秒留存 +8%”，或者在 INDEX 里标“（停用：原因）”。
- **做法**：改写那一段，不在文件末尾追加补丁。用户同意后再改。在 `频道复盘.md` 的“已升级”一节记一行：日期、规律、依据哪几期、改了哪个文件。
- **数据太少时不下结论**：频道还没有 5 期数据时，没有可靠的中位数。这时只和上一期比，写“待更多数据验证”。

## 5. 写下一期的 BRIEF 时

开工时读 `频道复盘.md` 的最近三行，和上一期 RETRO.md 里的“下一期试什么”。在 BRIEF 的“备选与取舍”里写一句：这期验证哪一条。
